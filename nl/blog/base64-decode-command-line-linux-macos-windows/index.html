Base64 decoderen op de opdrachtregel: Linux, macOS en Windows

November 2026 · 6 min. leestijd

Je hebt geen browser of script nodig om Base64 te decoderen. Elk groot besturingssysteem levert een hulpmiddel dat het in één regel doet, handig als je logs via SSH leest, een token in een pipeline inspecteert of een bestand uit een CI-variabele herstelt. Deze gids behandelt de opdrachten voor Linux, macOS en Windows en de kleine verschillen waardoor ze falen.

Linux: de opdracht base64

GNU coreutils bevat base64 op vrijwel elke distributie. Voeg -d (of --decode) toe om te decoderen:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

Gebruik printf '%s' of echo -n wanneer de waarde uit een variabele komt, zodat een afsluitend regeleinde geen deel van de invoer wordt:

printf '%s' "$TOKEN" | base64 -d

Om een bestand naar een ander bestand te decoderen, leid je de uitvoer om. Stuur binaire resultaten altijd naar een bestand en niet naar de terminal:

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

GNU-base64 tolereert regeleinden in de invoer maar weigert ander afval met base64: invalid input. De optie -i (--ignore-garbage) laat het tekens buiten het alfabet overslaan, wat nuttig is maar beschadigde gegevens kan verbergen, dus gebruik haar bewust.

macOS: hetzelfde gereedschap, iets andere vlaggen

macOS levert de BSD-versie mee. Oudere releases gebruiken een hoofdletter -D om te decoderen, en nieuwere accepteren ook -d. Geeft de ene vlag een fout, probeer dan de andere:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

Het BSD-gereedschap leest en schrijft bestanden met -i en -o:

base64 -D -i encoded.txt -o photo.png

Op macOS kun je ook rechtstreeks vanaf het klembord decoderen, de snelste manier om iets te inspecteren dat je zojuist hebt gekopieerd:

pbpaste | base64 -D

Op Linux gebruikt het equivalent xclip -o of wl-paste.

Windows: PowerShell

PowerShell kan .NET rechtstreeks aanroepen. FromBase64String geeft bytes terug, dus zet ze om in tekst wanneer de inhoud tekst is:

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

Een bestand herstellen uit Base64:

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

.NET negeert witruimte en regeleinden in de invoer, dus een afgebroken bestand of het afsluitende regeleinde van Get-Content -Raw is geen probleem. Bij ongeldige tekens en een verkeerde lengte geeft het wel een fout. Gebruik [IO.File]::WriteAllBytes met een volledig pad, want .NET lost relatieve paden op ten opzichte van de map van het proces en niet van je huidige PowerShell-locatie.

Windows: certutil

Het ingebouwde certutil werkt vanaf de klassieke opdrachtprompt en heeft geen PowerShell nodig:

certutil -decode encoded.txt photo.png

Het leest een bestand, geen standaardinvoer. Het accepteert ruwe Base64 en ook bestanden in PEM-stijl met -----BEGIN ...------markeringen, en toont een succesmelding met het aantal geschreven bytes.

Overal: openssl

Als OpenSSL is geïnstalleerd, gedraagt het zich op alle drie de systemen hetzelfde:

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

De vlag -A zegt dat de invoer op één regel staat. Zonder verwacht OpenSSL regeleinden om de 64 tekens en kan het bij een lange string op één regel falen of niets teruggeven.

Base64URL decoderen (JWT-delen en tokens)

Deze hulpmiddelen verwachten het standaardalfabet, dus Base64URL-invoer met - en _ of zonder =-opvulling geeft fouten. Converteer die eerst. Een herbruikbare shellfunctie:

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

Zie Base64 vs Base64URL voor waarom de alfabetten verschillen en hoe je JWT-claims inspecteert voor wat de payload bevat. Dezelfde logica in PowerShell is een replace van - en _ plus opvulling voordat je FromBase64String aanroept.

Controleer wat je hebt gedecodeerd

De gedecodeerde uitvoer kan tekst zijn of elk binair bestand. Bekijk hem voordat je hem opent of uitvoert:

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

Signaturen helpen: %PDF is een pdf, PK is een ZIP- of Office-bestand, en de Base64-tekst iVBORw0KGgo aan het begin van een string is een PNG. Voer nooit een gedecodeerd bestand uit dat je niet verwachtte. Meer hierover in binaire bestanden decoderen.

Problemen oplossen

  • invalid input (Linux) of error decoding (macOS): de waarde bevat waarschijnlijk een voorvoegsel data:...;base64,, URL-veilige tekens of verdwaalde aanhalingstekens. Verwijder die eerst.
  • De uitvoer is rommel: de inhoud is binair. Schrijf hem naar een bestand in plaats van naar de terminal.
  • Niets afgedrukt of afgekapt: controleer op een ontbrekend regeleinde, een ontbrekende -A bij OpenSSL, of dat de shell +, / of = bijzonder behandelde omdat de waarde niet tussen aanhalingstekens stond.
  • Werkt op Linux, mislukt op macOS: wissel tussen -d en -D.

Als een decodering op de opdrachtregel een waarde niet verduidelijkt, plak hem dan in decodeb64.com. Het herkent het alfabet, herstelt de opvulling en zegt of het resultaat tekst of een bestand is, alles lokaal in je browser.
