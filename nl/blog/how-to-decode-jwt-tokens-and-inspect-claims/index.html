Hoe je JWT-tokens decodeert en claims inspecteert

Augustus 2026 · 6 min. leestijd

JWT-tokens vormen de ruggengraat van moderne authenticatiesystemen. Of je nu een inlogprobleem debugt, inspecteert welke claims een API teruggeeft, of leert hoe OAuth 2.0 onder de motorkap werkt — weten hoe je een JWT decodeert is een essentiële vaardigheid voor ontwikkelaars. Deze gids leidt je stap voor stap door het proces.

De structuur van een JWT

Een JWT (JSON Web Token) bestaat uit drie delen, gescheiden door punten:

[header].[payload].[signature]

Een echte JWT ziet er zo uit:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

Elk deel gebruikt Base64URL-codering — niet standaard Base64. Base64URL vervangt + door -, / door _ en verwijdert de =-padding, waardoor het token veilig te gebruiken is in HTTP-headers en URL's.

Deel 1 — De header

Het eerste deel codeert een JSON-object dat het token beschrijft:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9

Gedecodeerd:

{"alg":"HS256","typ":"JWT"}

Het “alg”-veld vertelt de server welk cryptografisch algoritme is gebruikt om het token te ondertekenen. Veelvoorkomende waarden zijn HS256 (HMAC met SHA-256), RS256 (RSA met SHA-256) en ES256 (ECDSA met SHA-256).

Deel 2 — De payload (claims)

Het tweede deel codeert de claims — de data die het token bevat:

eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ

Gedecodeerd:

{"sub":"1234567890","name":"John Doe","iat":1516239022}

Standaard claim-namen:

  • sub (subject) — meestal de gebruikers-ID
  • iat (issued at) — Unix-tijdstempel van het aanmaken van het token
  • exp (expiration) — Unix-tijdstempel van verlopen — controleer dit bij het debuggen van “token verlopen”-fouten
  • iss (issuer) — de server of dienst die het token heeft aangemaakt
  • aud (audience) — de beoogde ontvanger van het token
  • jti (JWT ID) — een unieke identifier voor het token, gebruikt om replay-aanvallen te voorkomen

Aangepaste claims kunnen elke data bevatten: gebruikersrollen, rechten, e-mailadressen, abonnementsniveaus — wat de applicatie ook nodig heeft.

Deel 3 — De handtekening

Het derde deel is een cryptografische handtekening, geen Base64URL-gecodeerd JSON-object. Deze wordt gemaakt door de header en payload te hashen met een geheime sleutel. Je kunt het niet decoderen naar leesbare tekst — alleen de server met de geheime sleutel kan het verifiëren.

Een JWT stap voor stap decoderen

Stap 1: Kopieer de JWT-string uit je applicatie, de ontwikkelaarstools van de browser, of een API-antwoord.

Stap 2: Splits deze op de punten. Je krijgt drie delen. Het derde deel (de handtekening) kan niet worden gedecodeerd naar leesbare tekst.

Stap 3: Neem het eerste of tweede deel (header of payload) en plak het in decodeb64.com. De decoder verwerkt Base64URL automatisch — je hoeft - niet handmatig te vervangen door + of _ door /.

Stap 4: De gedecodeerde JSON toont de claims. Debug je een authenticatieprobleem, controleer dan eerst het exp-veld — zet de Unix-tijdstempel om naar een leesbare datum om te zien of het token is verlopen.

Decoderen versus verifiëren

Een cruciaal verschil: een JWT decoderen is niet hetzelfde als het verifiëren. Iedereen kan een JWT-payload decoderen en de claims lezen. Wat JWT's veilig maakt, is de handtekening — alleen de server met de juiste geheime sleutel kan verifiëren dat het token echt is en niet is gemanipuleerd.

Vertrouw JWT-claims in je applicatie nooit zonder de handtekening serverzijdig te verifiëren met een geschikte JWT-bibliotheek. Decoderen is alleen bedoeld voor inspectie en debuggen.

Veelvoorkomende JWT-debugscenario's

“Token is ongeldig” — Het token is mogelijk misvormd of beschadigd. Plak het in een decoder om de structuur te controleren.

“Token is verlopen” — Decodeer de payload en controleer de exp-claim. Zet de Unix-tijdstempel om om te bevestigen wanneer het token is verlopen.

“Claims kloppen niet” — Decodeer de payload om precies te zien welke claims het token bevat. Vaak is het token uitgegeven vóór een wijziging in rechten.

“Verificatie van de handtekening mislukt” — Dit kun je niet debuggen door te decoderen. Controleer of de server de juiste geheime of publieke sleutel gebruikt voor het algoritme in de header.

Probeer het nu

Plak je JWT in decodeb64.com. De tool detecteert automatisch Base64URL-codering en decodeert de header en payload. Je kunt ook de modus “Elke regel afzonderlijk decoderen” gebruiken als je meerdere tokens tegelijk wilt inspecteren.
