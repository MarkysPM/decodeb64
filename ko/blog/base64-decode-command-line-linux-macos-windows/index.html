명령줄에서 Base64 디코딩: Linux, macOS, Windows

2026년 11월 · 6 분 소요

Base64를 디코딩하는 데 브라우저나 스크립트는 필요 없습니다. 주요 운영 체제에는 모두 한 줄로 이를 처리하는 도구가 들어 있어, SSH로 로그를 읽거나, 파이프라인에서 토큰을 확인하거나, CI 변수에서 파일을 복원할 때 편리합니다. 이 가이드는 Linux, macOS, Windows의 명령과 이를 실패하게 만드는 작은 차이를 다룹니다.

Linux: base64 명령

GNU coreutils는 사실상 모든 배포판에 base64를 포함합니다. 디코딩하려면 -d(또는 --decode)를 붙입니다.

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

값이 변수에서 올 때는 끝의 줄바꿈이 입력에 포함되지 않도록 printf '%s'나 echo -n을 사용하세요.

printf '%s' "$TOKEN" | base64 -d

파일을 다른 파일로 디코딩하려면 출력을 리다이렉트하세요. 이진 결과는 터미널이 아니라 반드시 파일로 보내세요.

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

GNU base64는 입력의 줄바꿈은 허용하지만 그 밖의 쓰레기는 base64: invalid input으로 거부합니다. -i(--ignore-garbage) 옵션은 알파벳 밖의 문자를 건너뛰게 합니다. 유용하지만 손상된 데이터를 숨길 수 있으니 의도적으로 사용하세요.

macOS: 같은 도구, 약간 다른 플래그

macOS에는 BSD 버전이 들어 있습니다. 오래된 릴리스는 디코딩에 대문자 -D를 쓰고, 새 릴리스는 -d도 받아들입니다. 한쪽 플래그가 오류를 내면 다른 쪽을 써 보세요.

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

BSD 도구는 -i와 -o로 파일을 읽고 씁니다.

base64 -D -i encoded.txt -o photo.png

macOS에서는 클립보드에서 바로 디코딩할 수도 있어, 방금 복사한 것을 확인하는 가장 빠른 방법입니다.

pbpaste | base64 -D

Linux에서는 xclip -o나 wl-paste가 같은 역할을 합니다.

Windows: PowerShell

PowerShell은 .NET을 직접 호출할 수 있습니다. FromBase64String은 바이트를 반환하므로, 내용이 텍스트라면 텍스트로 변환하세요.

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

Base64에서 파일을 복원하려면 다음과 같이 합니다.

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

.NET은 입력의 공백과 줄바꿈을 무시하므로 줄바꿈된 파일이나 Get-Content -Raw의 끝 줄바꿈은 문제가 되지 않습니다. 유효하지 않은 문자와 잘못된 길이에는 오류를 던집니다. [IO.File]::WriteAllBytes에는 전체 경로를 사용하세요. .NET은 상대 경로를 PowerShell의 현재 위치가 아니라 프로세스 디렉터리를 기준으로 해석하기 때문입니다.

Windows: certutil

내장 certutil은 기존 명령 프롬프트에서 동작하며 PowerShell이 필요 없습니다.

certutil -decode encoded.txt photo.png

표준 입력이 아니라 파일을 읽습니다. 원시 Base64와 -----BEGIN ...----- 마커가 있는 PEM 형식 파일을 모두 받아들이고, 기록한 바이트 수가 담긴 성공 메시지를 출력합니다.

어디서나: openssl

OpenSSL이 설치되어 있다면 세 시스템 모두에서 똑같이 동작합니다.

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

-A 플래그는 입력이 한 줄이라고 알려 줍니다. 이것이 없으면 OpenSSL은 64자마다 줄바꿈을 기대하므로, 긴 한 줄 문자열에서는 실패하거나 아무것도 반환하지 않을 수 있습니다.

Base64URL 디코딩(JWT 부분과 토큰)

이 도구들은 표준 알파벳을 기대하므로, -와 _가 있거나 = 패딩이 없는 Base64URL 입력은 오류를 냅니다. 먼저 변환하세요. 재사용할 수 있는 셸 함수는 다음과 같습니다.

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

알파벳이 다른 이유는 Base64와 Base64URL을, 페이로드에 무엇이 들어 있는지는 JWT 클레임 확인 방법을 참고하세요. PowerShell에서 같은 논리는 FromBase64String을 호출하기 전에 -와 _를 치환하고 패딩을 추가하는 것입니다.

디코딩한 결과 확인하기

디코딩된 출력은 텍스트일 수도, 어떤 이진 파일일 수도 있습니다. 열거나 실행하기 전에 살펴보세요.

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

시그니처가 도움이 됩니다. %PDF는 PDF, PK는 ZIP이나 Office 파일, 문자열 시작 부분의 Base64 텍스트 iVBORw0KGgo는 PNG입니다. 예상하지 못한 디코딩된 파일은 절대 실행하지 마세요. 자세한 내용은 이진 파일 디코딩을 참고하세요.

문제 해결

  • invalid input(Linux) 또는 error decoding(macOS): 값에 data:...;base64, 접두사, URL 안전 문자, 또는 불필요한 따옴표가 포함되어 있을 가능성이 큽니다. 먼저 제거하세요.
  • 출력이 쓰레기: 내용이 이진입니다. 터미널 대신 파일에 쓰세요.
  • 아무것도 출력되지 않거나 잘림: 줄바꿈 누락, OpenSSL에서 -A 누락, 또는 값을 따옴표로 감싸지 않아 셸이 +, /, =를 특별하게 처리했는지 확인하세요.
  • Linux에서는 되는데 macOS에서 실패: -d와 -D를 바꿔 보세요.
