HTML 이메일과 웹 페이지에서 Base64 이미지를 디코딩하는 방법

2026년 11월 · 7 분 소요

때로는 필요한 이미지가 파일이 아니라 이메일이나 페이지 소스 코드 속의 아주 긴 문자열일 때가 있습니다. 뉴스레터, 청구서, 서명, 내보낸 보고서는 이미지를 Base64로 임베드하는 일이 많습니다. 어디에 숨어 있는지, 두 가지 임베드 방식 중 어느 것을 썼는지만 알면 꺼내는 것은 간단합니다.

이미지가 이메일 안에 들어가는 방식

HTML 이메일에 이미지를 넣는 일반적인 방법은 두 가지입니다.

  • HTML 안의 데이터 URI. 이미지가 마크업의 일부입니다: <img src="data:image/png;base64,iVBORw0KGgo...">. 구문은 데이터 URI 가이드를 참고하세요. Gmail을 비롯한 많은 이메일 클라이언트가 이를 표시하지 않으므로 실제 캠페인에서는 드뭅니다.
  • cid:로 참조되는 첨부 파트. 이메일은 여러 파트로 이루어진 MIME 메시지입니다. HTML에는 <img src="cid:logo123">이 있고, Content-ID: <logo123>과 Content-Transfer-Encoding: base64를 가진 별도 파트가 이미지 바이트를 담고 있습니다. 이메일의 인라인 이미지에 쓰는 표준적인 방법입니다.

둘 다 내부적으로는 Base64이지만, 추출 방법이 다릅니다.

경우 1: HTML 안의 데이터 URI

페이지 소스나 이메일의 HTML 보기를 열어 src="data:image/..." 속성을 찾으세요. 이미지를 가장 빨리 보는 방법은 data:image/png;base64, 접두사를 포함한 값 전체를 복사해 저희 Base64 이미지 변환기에 붙여 넣는 것입니다. 미리보기를 보여 주고, 아무것도 업로드하지 않은 채 PNG, JPG, WebP로 내려받을 수 있습니다.

큰 파일에서 모든 이미지를 자동으로 꺼내려면 짧은 Python 스크립트를 쓰세요.

import base64, re

html = open("page.html", encoding="utf-8").read()
pattern = r'data:image/(png|jpeg|gif|webp);base64,([A-Za-z0-9+/=\s]+)'

for i, (ext, b64) in enumerate(re.findall(pattern, html)):
    data = base64.b64decode("".join(b64.split()))
    with open(f"image{i}.{ext}", "wb") as f:
        f.write(data)

"".join(b64.split())은 이메일 시스템이 긴 줄을 줄바꿈하면서 넣은 줄바꿈을 제거합니다. Python에 대한 자세한 내용은 Python의 Base64를 참고하세요.

경우 2: .eml 파일의 첨부

메시지를 .eml로 저장하세요(대부분의 클라이언트에 "다운로드"나 "다른 이름으로 저장"이 있습니다). Python 표준 email 패키지는 MIME을 이해하고 Base64 디코딩을 대신 처리합니다.

from email import policy
from email.parser import BytesParser

with open("message.eml", "rb") as f:
    msg = BytesParser(policy=policy.default).parse(f)

for n, part in enumerate(msg.walk()):
    if part.get_content_maintype() != "image":
        continue
    data = part.get_payload(decode=True)      # Base64 already decoded
    name = part.get_filename()
    if not name:
        cid = (part["Content-ID"] or f"image{n}").strip("<>")
        name = f"{cid}.{part.get_content_subtype()}"
    with open(name, "wb") as out:
        out.write(data)

get_payload(decode=True)를 쓰면 라이브러리가 Content-Transfer-Encoding 헤더를 처리하므로, 파트가 Base64든 quoted-printable이든 동작합니다.

MIME 파트의 원시 텍스트만 있다면, Content-Transfer-Encoding: base64 아래 빈 줄 다음의 블록을 복사해 decodeb64.com이나 이미지 변환기에 붙여 넣으세요. 블록 안의 줄바꿈은 문제가 되지 않습니다.

경우 3: 브라우저에서

웹 페이지에서는 텍스트 단계를 완전히 건너뛸 수 있습니다.

  • 이미지를 마우스 오른쪽 버튼으로 클릭해 "새 탭에서 이미지 열기"를 선택한 뒤 저장하세요. 브라우저가 데이터 URI를 대신 디코딩합니다.
  • 또는 DevTools를 열어 Elements 패널에서 <img> 요소를 선택하고 src 속성을 복사하세요.
  • 콘솔에서 fetch(img.src).then(r => r.blob())은 디코딩된 바이트를 내려받을 수 있는 Blob으로 반환합니다.

처음 몇 글자로 형식 알아보기

데이터 URI 접두사가 없어도, Base64의 처음 몇 글자가 파일 형식을 드러냅니다.

  • iVBORw0KGgo — PNG
  • /9j/ — JPEG
  • R0lGOD — GIF
  • UklGR — WebP(RIFF 컨테이너)
  • PHN2Zy 또는 PD94bWw — SVG 또는 XML 텍스트
  • JVBERi0 — PDF(이미지가 아님)

이진 파일 디코딩 가이드에 더 긴 목록이 있습니다. 저장할 때는 올바른 확장자를 쓰세요. 그렇지 않으면 파일이 열리지 않을 수 있습니다.

아주 작은 이미지는 대개 추적기입니다

이메일에 1×1 픽셀 이미지가 있다면 거의 항상 메시지가 열렸는지 감지하는 추적 픽셀입니다. 디코딩하면 빈 정사각형이나 투명한 정사각형이 보일 것입니다. 데이터 URI 픽셀은 외부와 통신하지 않지만, URL에서 불러오는 픽셀은 통신합니다. 많은 클라이언트가 원격 이미지를 기본으로 차단하는 이유입니다.

결과를 안전하게 다루기

  • SVG에는 스크립트가 있을 수 있습니다. 모르는 이메일의 SVG를 브라우저에서 그대로 열거나 innerHTML로 페이지에 주입하지 마세요.
  • 선언된 형식을 믿지 마세요. image/png로 표시된 파트가 다른 무언가일 수 있습니다. 위에서 보인 대로 처음 몇 바이트를 확인하세요.
  • 피싱 메시지는 콘텐츠를 Base64에 숨깁니다. 자신의 컴퓨터에서 디코딩해 보는 것은 괜찮지만, 임베드된 링크를 클릭하거나 첨부 파일을 실행하는 것은 안 됩니다.
  • 개인정보. 개인 이미지를 온라인 도구에 붙여 넣으면, 도구가 로컬에서 동작하지 않는 한 업로드됩니다. decodeb64.com은 브라우저 안에서 디코딩하므로 데이터가 기기를 떠나지 않습니다.

디코딩이 실패한다면

흔한 용의자는 문자열에 남은 data:...;base64, 접두사, 값 안의 공백이나 HTML 엔티티(+ 대신 &#43; 같은 것), 저장 중 잘린 메시지입니다. Base64 디코딩이 실패하는 이유가 각 경우에 대한 짧은 체크리스트를 안내합니다.
