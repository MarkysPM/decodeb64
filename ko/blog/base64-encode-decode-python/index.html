Python의 Base64: 문자열, 파일, URL 인코딩과 디코딩

2026년 11월 · 7 분 소요

Python은 표준 base64 모듈에 Base64에 필요한 모든 것을 갖추고 있습니다. 대부분을 헷갈리게 하는 것은 API가 아니라 타입 시스템입니다. Base64는 *bytes*를 다루지만, 여러분의 데이터는 대부분 str로 시작합니다. 이 경계를 이해하면 나머지는 간단합니다.

문자열 인코딩

b64encode()는 bytes를 받아 bytes를 반환합니다. 텍스트를 인코딩하려면 먼저 bytes로 바꿔야 하고, 결과를 보여 주려면 보통 다시 문자열로 디코딩합니다.

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

str을 그대로 넘기면 TypeError: a bytes-like object is required, not 'str'가 납니다. 이 오류는 항상 .encode() 단계를 빼먹었다는 뜻입니다.

문자열 디코딩

b64decode()는 bytes 또는 ASCII만 있는 str을 받아 bytes를 반환합니다. 내용이 텍스트라면 올바른 문자 인코딩으로 바이트를 디코딩하세요.

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

인코딩은 항상 명시하세요. 예를 들어 "héllo"는 é가 UTF-8에서 2바이트를 차지하기 때문에 aMOpbGxv로 인코딩됩니다. 보낸 쪽이 Latin-1이나 UTF-16 같은 다른 인코딩을 썼다면 UTF-8로 디코딩할 때 UnicodeDecodeError가 나거나 글자가 깨집니다.

엄격한 검증

기본적으로 b64decode()는 관대해서, Base64 알파벳에 없는 문자를 조용히 버립니다. 줄바꿈이 있는 문자열에는 편리하지만 손상된 데이터를 숨길 수 있습니다. validate=True를 넘기면 유효하지 않은 문자에서 binascii.Error가 발생합니다.

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

"Incorrect padding" 고치기

Python에서 가장 흔한 Base64 오류는 binascii.Error: Incorrect padding입니다. 문자열 길이가 4의 배수가 아니라는 뜻이며, =가 제거된 Base64URL 값(JWT의 각 부분 등)에서 자주 발생합니다. 디코딩 전에 복원하세요.

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

식 -len(s) % 4는 부족한 문자 수(0, 1, 2, 3)를 줍니다. 나머지가 1글자인 길이는 유효한 Base64가 될 수 없으므로, 길이가 4의 배수보다 1 큰 문자열은 잘렸거나 손상된 것이며 어떤 패딩으로도 고칠 수 없습니다.

URL 안전 Base64

토큰, 식별자, URL에 들어가는 모든 것에는 +와 /를 -와 _로 바꾸는 URL 안전 변형을 사용하세요(Base64와 Base64URL 참고).

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

urlsafe_b64encode()는 패딩을 유지한다는 점에 유의하세요. JWT 같은 사양이 패딩 없는 형식을 요구하면 직접 제거하세요.

파일 인코딩과 디코딩

Python이 내용을 텍스트로 해석하지 않도록 파일은 이진 모드("rb"와 "wb")로 여세요.

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

파일로 데이터 URI를 만드는 데는 한 줄만 더 있으면 됩니다.

data_uri = f"data:image/png;base64,{b64}"

큰 파일은 전부 메모리에 올리지 마세요. 이 모듈은 base64.encode(input, output)와 base64.decode(input, output)를 제공하며, 두 이진 파일 객체 사이에서 스트리밍하고 인코딩 시 76자마다 줄바꿈을 넣습니다.

데이터 URI 또는 JWT 일부 디코딩

data:image/png;base64,는 Base64 데이터의 일부가 아니므로, 디코딩 전에 접두사를 제거하세요.

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

디버깅 중 JWT 페이로드를 들여다보려면 다음과 같이 합니다(이것은 서명을 검증하지 *않습니다*).

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

무엇을 안전하게 신뢰할 수 있는지는 JWT 디코딩 가이드에서 읽어 보세요.

모듈의 다른 함수

  • b32encode()와 b32decode(): Base32. TOTP 비밀 키처럼 사람이 읽기 쉬운 코드에 유용합니다.
  • b16encode()와 b16decode(): 단순 16진수.
  • a85encode()와 b85encode(): 더 촘촘한 인코딩(33%가 아닌 약 25% 증가). 대신 알파벳이 더 큽니다.

문제가 생겼을 때의 체크리스트

  • bytes 관련 TypeError: 인코딩 전에 .encode()를 호출하세요.
  • Incorrect padding: 문자열이 잘렸거나 =가 제거되었습니다. 4의 배수가 되도록 패딩하세요.
  • validate=True에서의 유효하지 않은 문자: 값이 Base64URL이거나, 공백을 포함하거나, 데이터 URI 접두사가 남아 있을 가능성이 큽니다.
  • UnicodeDecodeError: 디코딩된 바이트가 UTF-8 텍스트가 아닙니다. 이미지, 압축된 덩어리, 다른 인코딩일 수 있습니다.
