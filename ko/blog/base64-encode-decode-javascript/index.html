JavaScript의 Base64: btoa, atob와 유니코드 함정

2026년 11월 · 7 분 소요

JavaScript에는 Base64용 내장 함수 btoa()와 atob()가 있으며, ASCII에서는 완벽하게 동작합니다. 문제는 텍스트에 이모지, Latin-1 밖의 악센트 문자, 또는 이진 데이터가 들어가는 순간 시작됩니다. 이 가이드는 두 함수가 실제로 하는 일, 실패하는 이유, 그리고 브라우저와 Node.js 모두에서 통하는 패턴을 보여 줍니다.

기본: btoa와 atob

이름은 역사적인 것으로, btoa는 "binary to ASCII"(인코딩), atob는 "ASCII to binary"(디코딩)를 뜻합니다.

btoa('Hello, World!');
// "SGVsbG8sIFdvcmxkIQ=="

atob('SGVsbG8sIFdvcmxkIQ==');
// "Hello, World!"

두 함수는 모든 최신 브라우저, Web Worker, 그리고 현재 버전의 Node.js, Deno, Bun에서 전역으로 사용할 수 있습니다.

유니코드 문제

핵심은 btoa()가 "텍스트"를 받지 않는다는 점입니다. 이 함수는 *이진 문자열*을 받으며, 각 문자의 코드 포인트는 0에서 255 사이여야 하고 한 문자가 1바이트로 취급됩니다. 이를 넘으면 오류가 납니다.

btoa('€');
// Uncaught InvalidCharacterError: String contains an invalid character

btoa('你好');
// Uncaught InvalidCharacterError

é(U+00E9) 같은 문자는 0–255 범위에 들어가므로 btoa('café')는 동작하는 것처럼 보이지만, UTF-8이 아니라 Latin-1 바이트를 인코딩합니다. 결과를 UTF-8로 디코딩하는 다른 시스템에서는 깨진 문자가 보입니다. 안전한 방법은 먼저 문자열을 UTF-8 바이트로 바꾼 뒤 그 바이트를 인코딩하는 것입니다.

유니코드 텍스트를 올바르게 인코딩하기

TextEncoder로 UTF-8 바이트를 얻고, 이진 문자열로 바꾼 다음 btoa()를 호출합니다.

function encodeBase64(text) {
  const bytes = new TextEncoder().encode(text);
  let binary = '';
  bytes.forEach(b => { binary += String.fromCharCode(b); });
  return btoa(binary);
}

encodeBase64('€');      // "4oKs"
encodeBase64('你好');   // "5L2g5aW9"

반대 방향은 TextDecoder를 사용합니다.

function decodeBase64(b64) {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new TextDecoder().decode(bytes);
}

decodeBase64('4oKs');   // "€"

입력이 매우 크면 문자열을 한 글자씩 쌓는 것이 느립니다. 속도 저하와 호출 스택 제한을 피하려면 바이트를 청크 단위(예: String.fromCharCode.apply로 한 번에 32,768개)로 처리하세요.

Node.js: Buffer 사용

Node.js에서는 Buffer가 UTF-8과 이진 데이터를 직접 다루므로 우회책이 필요 없습니다.

Buffer.from('€', 'utf8').toString('base64');
// "4oKs"

Buffer.from('4oKs', 'base64').toString('utf8');
// "€"

// Base64URL (Node.js 15.7+ and 14.18+)
Buffer.from('hello?>', 'utf8').toString('base64url');

파일에도 Buffer가 적합합니다. 파일을 곧바로 buffer로 읽어 .toString('base64')를 호출하면 바이트 문자열을 중간에 만들 필요가 없습니다.

브라우저에서의 이진 데이터

사용자가 선택한 파일을 인코딩하려면 보통 FileReader.readAsDataURL()이 가장 간단합니다. 결과는 데이터 URI이며, Base64 부분은 쉼표 뒤의 모든 것입니다.

const reader = new FileReader();
reader.onload = () => {
  const dataUri = reader.result;           // "data:image/png;base64,iVBORw0..."
  const base64  = dataUri.split(',')[1];   // just the Base64 payload
};
reader.readAsDataURL(file);

반대로 Base64를 다운로드 가능한 파일이나 이미지 URL로 되돌리려면 Uint8Array로 디코딩하고, Blob으로 감싸고, 객체 URL을 만듭니다.

function base64ToBlob(b64, type = 'application/octet-stream') {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new Blob([bytes], { type });
}

const url = URL.createObjectURL(base64ToBlob(b64, 'image/png'));
img.src = url;

온라인 Base64 이미지 변환기가 내부에서 하는 일이 바로 이것입니다. 저희 Base64 이미지 변환기도 같은 방식으로 브라우저 안에서만 동작하므로 아무것도 업로드되지 않습니다.

JavaScript의 Base64URL

브라우저에는 URL 안전 알파벳용 btoa에 해당하는 내장 함수가 없으므로 문자를 직접 변환하세요(Base64와 Base64URL 참고).

const toBase64Url = b64 =>
  b64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

const fromBase64Url = s => {
  let b64 = s.replace(/-/g, '+').replace(/_/g, '/');
  while (b64.length % 4) b64 += '=';
  return b64;
};

오류 처리

입력에 Base64 알파벳 밖의 문자가 있으면 atob()는 InvalidCharacterError를 던집니다. ASCII 공백은 무시하므로 긴 문자열 안의 줄바꿈은 문제가 없고, 현재 구현은 길이가 불가능한 값만 아니라면 패딩 누락도 받아들입니다(길이 4n+1은 절대 유효하지 않습니다). 신뢰할 수 없는 입력의 디코딩은 항상 try/catch로 감싸세요.

function safeDecode(b64) {
  try {
    return atob(b64.trim());
  } catch (e) {
    return null;   // not valid Base64
  }
}

빠른 참조

  • 브라우저의 ASCII 텍스트: btoa / atob.
  • 모든 유니코드 텍스트: btoa나 atob를 TextEncoder나 TextDecoder로 감싸기.
  • Node.js: Buffer.from(...).toString('base64'), 'base64url'도 지원.
  • 브라우저의 파일: 인코딩은 FileReader.readAsDataURL(), 디코딩은 Blob과 URL.createObjectURL().
  • 문자열이 유효하다고 가정하지 마세요: 오류를 잡고 공백을 다듬으세요.
