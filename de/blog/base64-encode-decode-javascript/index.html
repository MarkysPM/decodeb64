Base64 in JavaScript: btoa, atob und die Unicode-Fallen

November 2026 · 7 Min. Lesezeit

JavaScript bietet zwei eingebaute Funktionen für Base64, btoa() und atob(), und sie funktionieren mit reinem ASCII einwandfrei. Die Probleme beginnen, sobald Ihr Text ein Emoji, einen Buchstaben mit Akzent außerhalb von Latin-1 oder Binärdaten enthält. Diese Anleitung zeigt, was die Funktionen wirklich tun, warum sie fehlschlagen und welche Muster im Browser und in Node.js funktionieren.

Die Grundlagen: btoa und atob

Die Namen sind historisch: btoa bedeutet „binary to ASCII“ (kodieren) und atob „ASCII to binary“ (dekodieren).

btoa('Hello, World!');
// "SGVsbG8sIFdvcmxkIQ=="

atob('SGVsbG8sIFdvcmxkIQ==');
// "Hello, World!"

Beide sind in allen modernen Browsern, in Web Workern und als Globals in aktuellen Versionen von Node.js, Deno und Bun verfügbar.

Das Unicode-Problem

Das entscheidende Detail: btoa() nimmt keinen „Text“. Sie nimmt einen *Binärstring*, bei dem jedes Zeichen einen Codepoint zwischen 0 und 255 haben muss und als ein Byte behandelt wird. Alles darüber löst einen Fehler aus:

btoa('€');
// Uncaught InvalidCharacterError: String contains an invalid character

btoa('你好');
// Uncaught InvalidCharacterError

Zeichen wie é (U+00E9) liegen im Bereich 0–255, daher scheint btoa('café') zu funktionieren, kodiert aber das Latin-1-Byte statt UTF-8. Ein anderes System, das das Ergebnis als UTF-8 dekodiert, zeigt ein kaputtes Zeichen. Der sichere Weg ist, den String zuerst in UTF-8-Bytes umzuwandeln und diese zu kodieren.

Unicode-Text korrekt kodieren

Verwenden Sie TextEncoder, um UTF-8-Bytes zu erhalten, wandeln Sie sie in einen Binärstring um und rufen Sie dann btoa() auf:

function encodeBase64(text) {
  const bytes = new TextEncoder().encode(text);
  let binary = '';
  bytes.forEach(b => { binary += String.fromCharCode(b); });
  return btoa(binary);
}

encodeBase64('€');      // "4oKs"
encodeBase64('你好');   // "5L2g5aW9"

Und umgekehrt mit TextDecoder:

function decodeBase64(b64) {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new TextDecoder().decode(bytes);
}

decodeBase64('4oKs');   // "€"

Bei sehr großen Eingaben ist es langsam, den String Zeichen für Zeichen aufzubauen. Verarbeiten Sie die Bytes in Blöcken (zum Beispiel 32.768 auf einmal mit String.fromCharCode.apply), um sowohl die Verlangsamung als auch Call-Stack-Grenzen zu vermeiden.

Node.js: Buffer verwenden

In Node.js verarbeitet Buffer UTF-8 und Binärdaten direkt, ohne Umwege:

Buffer.from('€', 'utf8').toString('base64');
// "4oKs"

Buffer.from('4oKs', 'base64').toString('utf8');
// "€"

// Base64URL (Node.js 15.7+ and 14.18+)
Buffer.from('hello?>', 'utf8').toString('base64url');

Buffer ist auch das richtige Werkzeug für Dateien, denn Sie können eine Datei direkt in einen Buffer lesen und .toString('base64') aufrufen, ohne je einen String aus Bytes zu erzeugen.

Binärdaten im Browser

Um eine vom Benutzer gewählte Datei zu kodieren, ist FileReader.readAsDataURL() meist am einfachsten. Das Ergebnis ist eine Data-URI, und der Base64-Teil ist alles nach dem Komma:

const reader = new FileReader();
reader.onload = () => {
  const dataUri = reader.result;           // "data:image/png;base64,iVBORw0..."
  const base64  = dataUri.split(',')[1];   // just the Base64 payload
};
reader.readAsDataURL(file);

Für den umgekehrten Weg, also Base64 in eine herunterladbare Datei oder eine Bild-URL zu verwandeln, dekodieren Sie in ein Uint8Array, packen es in einen Blob und erzeugen eine Objekt-URL:

function base64ToBlob(b64, type = 'application/octet-stream') {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new Blob([bytes], { type });
}

const url = URL.createObjectURL(base64ToBlob(b64, 'image/png'));
img.src = url;

Genau das macht ein Online-Konverter von Base64 zu Bild im Hintergrund. Unser Base64-zu-Bild-Tool läuft mit demselben Ansatz vollständig in Ihrem Browser, es wird also nichts hochgeladen.

Base64URL in JavaScript

Browser haben kein eingebautes btoa-Pendant für das URL-sichere Alphabet, konvertieren Sie die Zeichen also selbst (siehe Base64 vs. Base64URL):

const toBase64Url = b64 =>
  b64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

const fromBase64Url = s => {
  let b64 = s.replace(/-/g, '+').replace(/_/g, '/');
  while (b64.length % 4) b64 += '=';
  return b64;
};

Fehlerbehandlung

atob() wirft einen InvalidCharacterError, wenn die Eingabe Zeichen außerhalb des Base64-Alphabets enthält. Sie ignoriert ASCII-Leerraum, Zeilenumbrüche in einem langen String sind also unproblematisch, und aktuelle Implementierungen akzeptieren fehlendes Auffüllen, solange die Länge nicht unmöglich ist (eine Länge von 4n+1 ist nie gültig). Umschließen Sie das Dekodieren nicht vertrauenswürdiger Eingaben immer mit try/catch:

function safeDecode(b64) {
  try {
    return atob(b64.trim());
  } catch (e) {
    return null;   // not valid Base64
  }
}

Kurzreferenz

  • ASCII-Text im Browser: btoa / atob.
  • Beliebiger Unicode-Text: TextEncoder bzw. TextDecoder um btoa bzw. atob.
  • Node.js: Buffer.from(...).toString('base64'), das auch 'base64url' unterstützt.
  • Dateien im Browser: FileReader.readAsDataURL() zum Kodieren, Blob plus URL.createObjectURL() zum Dekodieren.
  • Nie annehmen, dass der String gültig ist: Fehler abfangen und Leerraum entfernen.
