Base64 in Python: Strings, Dateien und URLs kodieren und dekodieren

November 2026 · 7 Min. Lesezeit

Python liefert alles, was Sie für Base64 brauchen, im Standardmodul base64 mit. Was die meisten verwirrt, ist nicht die API, sondern das Typsystem: Base64 arbeitet mit *Bytes*, während die meisten Ihrer Daten als str beginnen. Wenn Sie diese Grenze verstanden haben, ist der Rest einfach.

Einen String kodieren

b64encode() nimmt Bytes und gibt Bytes zurück. Um Text zu kodieren, müssen Sie ihn zuerst in Bytes umwandeln, und um das Ergebnis anzuzeigen, dekodieren Sie es meist wieder zu einem String:

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

Wird direkt ein str übergeben, entsteht TypeError: a bytes-like object is required, not 'str'. Dieser Fehler bedeutet immer, dass Sie den Schritt .encode() vergessen haben.

Einen String dekodieren

b64decode() akzeptiert Bytes oder einen reinen ASCII-str und gibt Bytes zurück. Handelt es sich um Text, dekodieren Sie die Bytes mit der richtigen Zeichenkodierung:

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

Geben Sie die Kodierung immer ausdrücklich an. Zum Beispiel wird "héllo" zu aMOpbGxv kodiert, weil das é in UTF-8 zwei Bytes belegt. Hat der Absender eine andere Kodierung wie Latin-1 oder UTF-16 verwendet, führt das Dekodieren als UTF-8 zu UnicodeDecodeError oder zu unlesbarem Text.

Strikte Validierung

Standardmäßig ist b64decode() nachsichtig: Es verwirft stillschweigend Zeichen, die nicht im Base64-Alphabet stehen. Das ist bei Zeilenumbrüchen praktisch, kann aber beschädigte Daten verbergen. Mit validate=True wird bei jedem ungültigen Zeichen binascii.Error ausgelöst:

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

„Incorrect padding“ beheben

Der häufigste Base64-Fehler in Python ist binascii.Error: Incorrect padding. Er bedeutet, dass die Stringlänge kein Vielfaches von vier ist, was oft bei Base64URL-Werten (etwa JWT-Teilen) passiert, deren = entfernt wurden. Stellen Sie sie vor dem Dekodieren wieder her:

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

Der Ausdruck -len(s) % 4 liefert die Anzahl fehlender Zeichen (0, 1, 2 oder 3). Ein Rest von einem Zeichen ist nie gültiges Base64; ein String, dessen Länge um eins über einem Vielfachen von vier liegt, ist also abgeschnitten oder beschädigt, und kein Auffüllen repariert das.

URL-sicheres Base64

Für Tokens, Kennungen und alles, was in einer URL landet, nutzen Sie die URL-sicheren Varianten, die + und / durch - und _ ersetzen (siehe Base64 vs. Base64URL):

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

Beachten Sie, dass urlsafe_b64encode() das Auffüllen beibehält. Entfernen Sie es selbst, wenn eine Spezifikation wie JWT die Form ohne Auffüllung verlangt.

Dateien kodieren und dekodieren

Öffnen Sie Dateien im Binärmodus ("rb" und "wb"), damit Python den Inhalt nicht als Text zu deuten versucht:

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

Eine Data-URI aus einer Datei zu bauen, erfordert nur eine weitere Zeile:

data_uri = f"data:image/png;base64,{b64}"

Bei großen Dateien sollten Sie nicht alles in den Speicher laden. Das Modul bietet base64.encode(input, output) und base64.decode(input, output), die zwischen zwei binären Dateiobjekten streamen und beim Kodieren alle 76 Zeichen einen Zeilenumbruch einfügen.

Eine Data-URI oder einen JWT-Teil dekodieren

Entfernen Sie das Präfix vor dem Dekodieren, denn data:image/png;base64, ist nicht Teil der Base64-Daten:

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

Um beim Debuggen einen Blick in die Payload eines JWT zu werfen (dies verifiziert die Signatur *nicht*):

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

Was Sie sicher als vertrauenswürdig annehmen dürfen, lesen Sie in unserer JWT-Dekodieranleitung.

Weitere Funktionen im Modul

  • b32encode() und b32decode(): Base32, nützlich für gut lesbare Codes wie TOTP-Secrets.
  • b16encode() und b16decode(): schlichtes Hexadezimal.
  • a85encode() und b85encode(): dichtere Kodierungen (etwa 25 % Zuwachs statt 33 %) zum Preis eines größeren Alphabets.

Checkliste, wenn etwas fehlschlägt

  • TypeError wegen bytes: .encode() vor dem Kodieren aufrufen.
  • Incorrect padding: Der String wurde abgeschnitten oder die = wurden entfernt; auf ein Vielfaches von vier auffüllen.
  • Ungültige Zeichen mit validate=True: Der Wert ist vermutlich Base64URL, enthält Leerraum oder trägt noch ein Data-URI-Präfix.
  • UnicodeDecodeError: Die dekodierten Bytes sind kein UTF-8-Text. Es kann ein Bild, ein komprimierter Blob oder eine andere Kodierung sein.
