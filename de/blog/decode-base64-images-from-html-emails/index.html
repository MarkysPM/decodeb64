Base64-Bilder aus HTML-E-Mails und Webseiten dekodieren

November 2026 · 7 Min. Lesezeit

Manchmal ist das gesuchte Bild keine Datei, sondern ein sehr langer String in einer E-Mail oder im Quellcode einer Seite. Newsletter, Rechnungen, Signaturen und exportierte Berichte betten Bilder oft als Base64 ein. Sie wieder herauszuholen ist einfach, sobald Sie wissen, wo sie stecken und welche der beiden Einbettungsmethoden verwendet wurde.

Wie Bilder in E-Mails gelangen

Es gibt zwei übliche Wege, ein Bild in eine HTML-E-Mail zu bringen:

  • Data-URI im HTML. Das Bild ist Teil des Markups: <img src="data:image/png;base64,iVBORw0KGgo...">. Die Syntax finden Sie in unserer Anleitung zu Data-URIs. Viele E-Mail-Clients, darunter Gmail, zeigen sie nicht an, daher sind sie in echten Kampagnen seltener.
  • Angehängter Teil, per cid: referenziert. Die E-Mail ist eine MIME-Nachricht mit mehreren Teilen. Das HTML enthält <img src="cid:logo123">, und ein separater Teil mit Content-ID: <logo123> und Content-Transfer-Encoding: base64 trägt die Bildbytes. Das ist der Standardweg für Inline-Bilder in E-Mails.

Beide sind unter der Haube Base64, werden aber unterschiedlich extrahiert.

Fall 1: eine Data-URI im HTML

Öffnen Sie den Seitenquelltext oder die HTML-Ansicht der E-Mail und suchen Sie das Attribut src="data:image/...". Am schnellsten sehen Sie das Bild, indem Sie den gesamten Wert samt Präfix data:image/png;base64, kopieren und in unseren Base64-zu-Bild-Konverter einfügen. Er zeigt eine Vorschau und lässt Sie das Bild als PNG, JPG oder WebP herunterladen, ohne etwas hochzuladen.

Um alle Bilder aus einer großen Datei automatisch zu extrahieren, nutzen Sie ein kurzes Python-Skript:

import base64, re

html = open("page.html", encoding="utf-8").read()
pattern = r'data:image/(png|jpeg|gif|webp);base64,([A-Za-z0-9+/=\s]+)'

for i, (ext, b64) in enumerate(re.findall(pattern, html)):
    data = base64.b64decode("".join(b64.split()))
    with open(f"image{i}.{ext}", "wb") as f:
        f.write(data)

"".join(b64.split()) entfernt die Zeilenumbrüche, die E-Mail-Systeme beim Umbrechen langer Zeilen einfügen. Weitere Python-Details finden Sie unter Base64 in Python.

Fall 2: Anhänge in einer .eml-Datei

Speichern Sie die Nachricht als .eml (die meisten Clients bieten „Herunterladen“ oder „Speichern unter“). Das Standardpaket email von Python versteht MIME und übernimmt die Base64-Dekodierung für Sie:

from email import policy
from email.parser import BytesParser

with open("message.eml", "rb") as f:
    msg = BytesParser(policy=policy.default).parse(f)

for n, part in enumerate(msg.walk()):
    if part.get_content_maintype() != "image":
        continue
    data = part.get_payload(decode=True)      # Base64 already decoded
    name = part.get_filename()
    if not name:
        cid = (part["Content-ID"] or f"image{n}").strip("<>")
        name = f"{cid}.{part.get_content_subtype()}"
    with open(name, "wb") as out:
        out.write(data)

Mit get_payload(decode=True) verarbeitet die Bibliothek den Header Content-Transfer-Encoding, es funktioniert also, ob der Teil Base64 oder Quoted-Printable ist.

Haben Sie nur den Rohtext eines MIME-Teils, kopieren Sie den Block, der auf die Leerzeile unter Content-Transfer-Encoding: base64 folgt, und fügen Sie ihn in decodeb64.com oder den Bildkonverter ein. Zeilenumbrüche im Block sind kein Problem.

Fall 3: aus dem Browser

Auf einer Webseite können Sie den Text ganz umgehen:

  • Rechtsklick auf das Bild, „Bild in neuem Tab öffnen“ wählen und speichern. Browser dekodieren Data-URIs für Sie.
  • Oder DevTools öffnen, das <img>-Element im Elements-Panel auswählen und das Attribut src kopieren.
  • In der Konsole liefert fetch(img.src).then(r => r.blob()) die dekodierten Bytes als Blob, den Sie herunterladen können.

Das Format an den ersten Zeichen erkennen

Fehlt das Data-URI-Präfix, verraten die ersten Zeichen des Base64 den Dateityp:

  • iVBORw0KGgo — PNG
  • /9j/ — JPEG
  • R0lGOD — GIF
  • UklGR — WebP (RIFF-Container)
  • PHN2Zy oder PD94bWw — SVG oder XML-Text
  • JVBERi0 — ein PDF, kein Bild

Unsere Anleitung zum Dekodieren von Binärdateien enthält eine längere Liste. Verwenden Sie beim Speichern die richtige Endung, sonst lässt sich die Datei womöglich nicht öffnen.

Winzige Bilder sind meist Tracker

Enthält eine E-Mail ein Bild mit 1×1 Pixel, ist es fast immer ein Tracking-Pixel, mit dem erkannt wird, dass die Nachricht geöffnet wurde. Dekodiert zeigt es ein leeres oder transparentes Quadrat. Pixel als Data-URI melden sich nirgends, ein von einer URL geladenes Pixel dagegen schon; deshalb blockieren viele Clients Remote-Bilder standardmäßig.

Ergebnisse sicher behandeln

  • SVG kann Skripte enthalten. Öffnen Sie ein SVG aus einer unbekannten E-Mail nicht direkt im Browser und fügen Sie es nie mit innerHTML in eine Seite ein.
  • Dem deklarierten Typ nicht trauen. Ein als image/png gekennzeichneter Teil kann etwas anderes sein. Prüfen Sie die ersten Bytes wie oben gezeigt.
  • Phishing-Nachrichten verstecken Inhalte in Base64. Dekodieren und Ansehen auf Ihrem eigenen Rechner ist in Ordnung; das Anklicken eingebetteter Links oder das Ausführen angehängter Dateien nicht.
  • Datenschutz. Ein privates Bild in ein Online-Werkzeug einzufügen, lädt es hoch, sofern das Werkzeug nicht lokal arbeitet. decodeb64.com dekodiert in Ihrem Browser, die Daten verlassen also nie Ihr Gerät.

Wenn die Dekodierung fehlschlägt

Die üblichen Verdächtigen sind das im String verbliebene Präfix data:...;base64,, Leerraum oder HTML-Entities im Wert (etwa &#43; statt +) und eine beim Speichern abgeschnittene Nachricht. Warum Base64-Dekodierung fehlschlägt geht für jeden Fall eine kurze Liste durch.
