Come decodificare i token JWT e ispezionare i claims

Agosto 2026 · 6 min di lettura

I token JWT sono la spina dorsale dei moderni sistemi di autenticazione. Che stiate facendo il debug di un problema di login, ispezionando quali claims restituisce un'API, o imparando come funziona OAuth 2.0 sotto il cofano, saper decodificare un JWT è una competenza essenziale per uno sviluppatore. Questa guida vi accompagna passo passo nel processo.

La struttura di un JWT

Un JWT (JSON Web Token) è composto da tre parti separate da punti:

[header].[payload].[signature]

Un JWT reale ha questo aspetto:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

Ogni parte usa la codifica Base64URL — non Base64 standard. Base64URL sostituisce + con -, / con _ e rimuove il padding =, rendendo il token sicuro da usare in header HTTP e URL.

Parte 1 — L'header

La prima parte codifica un oggetto JSON che descrive il token:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9

Decodificato:

{"alg":"HS256","typ":"JWT"}

Il campo “alg” indica al server quale algoritmo crittografico è stato usato per firmare il token. Valori comuni includono HS256 (HMAC con SHA-256), RS256 (RSA con SHA-256) ed ES256 (ECDSA con SHA-256).

Parte 2 — Il payload (claims)

La seconda parte codifica i claims — i dati trasportati dal token:

eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ

Decodificato:

{"sub":"1234567890","name":"John Doe","iat":1516239022}

Nomi standard dei claims:

  • sub (subject) — di solito l'ID utente
  • iat (issued at) — timestamp Unix di creazione del token
  • exp (expiration) — timestamp Unix di scadenza — controllatelo quando fate debug di errori “token scaduto”
  • iss (issuer) — il server o servizio che ha creato il token
  • aud (audience) — il destinatario previsto del token
  • jti (JWT ID) — un identificatore univoco del token, usato per prevenire attacchi di replay

I claims personalizzati possono contenere qualsiasi dato: ruoli utente, permessi, indirizzi email, livelli di abbonamento — qualunque cosa serva all'applicazione.

Parte 3 — La firma

La terza parte è una firma crittografica, non un oggetto JSON codificato in Base64URL. Viene creata calcolando l'hash di header e payload con una chiave segreta. Non è possibile decodificarla in testo leggibile: solo il server in possesso della chiave segreta può verificarla.

Come decodificare un JWT passo passo

Passo 1: Copiate la stringa JWT dalla vostra applicazione, dagli strumenti per sviluppatori del browser o da una risposta API.

Passo 2: Suddividetela in base ai punti. Otterrete tre parti. La terza parte (firma) non può essere decodificata in testo leggibile.

Passo 3: Prendete la prima o la seconda parte (header o payload) e incollatela in decodeb64.com. Il decoder gestisce Base64URL automaticamente — non serve sostituire manualmente - con + o _ con /.

Passo 4: Il JSON decodificato mostra i claims. Se state facendo debug di un problema di autenticazione, controllate prima il campo exp — convertite il timestamp Unix in una data leggibile per vedere se il token è scaduto.

Decodifica vs verifica

Una distinzione fondamentale: decodificare un JWT non è la stessa cosa che verificarlo. Chiunque può decodificare un payload JWT e leggerne i claims. Ciò che rende sicuri i JWT è la firma — solo il server con la chiave segreta corretta può verificare che il token sia autentico e non sia stato manomesso.

Non fidatevi mai dei claims JWT nella vostra applicazione senza verificare la firma lato server con una libreria JWT adeguata. La decodifica serve solo per l'ispezione e il debug.

Scenari comuni di debug JWT

“Il token non è valido” — Il token potrebbe essere malformato o corrotto. Incollatelo in un decoder per controllarne la struttura.

“Il token è scaduto” — Decodificate il payload e controllate il claim exp. Convertite il timestamp Unix per confermare quando è scaduto il token.

“I claims sono sbagliati” — Decodificate il payload per vedere esattamente quali claims contiene il token. Spesso il problema è che il token è stato emesso prima di una modifica dei permessi.

“Verifica della firma fallita” — Non è possibile fare debug decodificando. Controllate che il server usi la chiave segreta o pubblica corretta per l'algoritmo indicato nell'header.

Provalo ora

Incollate il vostro JWT in decodeb64.com. Lo strumento rileva automaticamente la codifica Base64URL e decodifica header e payload. Potete anche usare la modalità “Decodifica ogni riga separatamente” se dovete ispezionare più token contemporaneamente.

Decodificare token JWT è un'attività quotidiana per gli sviluppatori backend e frontend che lavorano con sistemi di autenticazione. Comprendere la struttura in tre parti e la differenza tra decodifica e verifica vi mette in controllo quando emergono problemi di autenticazione.
