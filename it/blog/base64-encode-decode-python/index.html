Base64 in Python: codificare e decodificare stringhe, file e URL

Novembre 2026 · 7 min di lettura

Python include tutto ciò che serve per Base64 nel modulo standard base64. Ciò che confonde la maggior parte delle persone non è l'API ma il sistema dei tipi: Base64 lavora su *bytes*, mentre quasi tutti i tuoi dati nascono come str. Una volta capito questo confine, il resto è semplice.

Codificare una stringa

b64encode() riceve bytes e restituisce bytes. Per codificare del testo devi prima convertirlo in bytes e, per mostrare il risultato, di solito lo decodifichi di nuovo in stringa:

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

Passare direttamente una str solleva TypeError: a bytes-like object is required, not 'str'. Questo errore significa sempre che hai dimenticato il passaggio .encode().

Decodificare una stringa

b64decode() accetta bytes o una str solo ASCII e restituisce bytes. Se il contenuto è testo, decodifica i bytes con la codifica di caratteri corretta:

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

Specifica sempre la codifica in modo esplicito. Per esempio, "héllo" si codifica come aMOpbGxv perché la é occupa due byte in UTF-8. Se il mittente ha usato un'altra codifica, come Latin-1 o UTF-16, decodificare come UTF-8 solleverà UnicodeDecodeError o produrrà testo illeggibile.

Validazione rigorosa

Per impostazione predefinita b64decode() è permissivo: scarta in silenzio i caratteri che non fanno parte dell'alfabeto Base64. È comodo con le interruzioni di riga, ma può nascondere dati corrotti. Passa validate=True per fargli sollevare binascii.Error su qualsiasi carattere non valido:

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

Correggere «Incorrect padding»

L'errore Base64 più comune in Python è binascii.Error: Incorrect padding. Significa che la lunghezza della stringa non è un multiplo di quattro, cosa frequente con valori Base64URL (come le parti di un JWT) a cui sono stati tolti i =. Ripristinali prima di decodificare:

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

L'espressione -len(s) % 4 dà il numero di caratteri mancanti (0, 1, 2 o 3). Un resto di 1 carattere non è mai Base64 valido, quindi una stringa la cui lunghezza supera di uno un multiplo di quattro è troncata o corrotta e nessun riempimento la sistemerà.

Base64 sicuro per gli URL

Per token, identificatori e tutto ciò che finisce in un URL, usa le varianti URL-safe, che sostituiscono + e / con - e _ (vedi Base64 vs Base64URL):

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

Nota che urlsafe_b64encode() mantiene il riempimento. Toglilo tu quando una specifica come JWT richiede la forma senza riempimento.

Codificare e decodificare file

Apri i file in modalità binaria ("rb" e "wb") in modo che Python non cerchi di interpretare il contenuto come testo:

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

Costruire un data URI da un file richiede solo una riga in più:

data_uri = f"data:image/png;base64,{b64}"

Per i file grandi, evita di caricare tutto in memoria. Il modulo offre base64.encode(input, output) e base64.decode(input, output), che trasmettono in streaming tra due oggetti file binari e inseriscono un'interruzione di riga ogni 76 caratteri in fase di codifica.

Decodificare un data URI o una parte di JWT

Rimuovi il prefisso prima di decodificare, perché data:image/png;base64, non fa parte dei dati Base64:

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

Per dare un'occhiata al payload di un JWT durante il debug (questo *non* verifica la firma):

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

Leggi di più su cosa è sicuro considerare attendibile nella nostra guida alla decodifica dei JWT.

Altre funzioni del modulo

  • b32encode() e b32decode(): Base32, utile per codici leggibili come i segreti TOTP.
  • b16encode() e b16decode(): esadecimale semplice.
  • a85encode() e b85encode(): codifiche più dense (circa 25 % di aumento invece del 33 %), al prezzo di un alfabeto più grande.

Checklist quando qualcosa non va

  • TypeError sui bytes: chiama .encode() prima di codificare.
  • Incorrect padding: la stringa è stata troncata o i = sono stati rimossi; completa fino a un multiplo di quattro.
  • Caratteri non validi con validate=True: il valore è probabilmente Base64URL, contiene spazi o ha ancora il prefisso di un data URI.
  • UnicodeDecodeError: i byte decodificati non sono testo UTF-8. Possono essere un'immagine, un blob compresso o un'altra codifica.
