HTML ईमेल और वेब पेजों से Base64 इमेज कैसे डिकोड करें

नवंबर 2026 · 7 मिनट का पठन

कभी-कभी जो इमेज आपको चाहिए वह फ़ाइल नहीं होती, बल्कि किसी ईमेल या पेज के सोर्स कोड के भीतर की एक बहुत लंबी स्ट्रिंग होती है। न्यूज़लेटर, इनवॉइस, हस्ताक्षर और एक्सपोर्ट की गई रिपोर्टें अक्सर इमेज को Base64 के रूप में एम्बेड करती हैं। उन्हें वापस निकालना आसान है, बशर्ते आपको पता हो कि वे कहाँ छिपी हैं और एम्बेड करने की दोनों विधियों में से कौन-सी इस्तेमाल हुई है।

इमेज ईमेल के भीतर कैसे पहुँचती हैं

HTML ईमेल में इमेज डालने के दो आम तरीके हैं:

  • HTML में डेटा URI। इमेज मार्कअप का हिस्सा होती है: <img src="data:image/png;base64,iVBORw0KGgo...">। सिंटैक्स के लिए हमारी डेटा URI गाइड देखें। Gmail सहित कई ईमेल क्लाइंट इन्हें नहीं दिखाते, इसलिए असली कैंपेन में ये कम मिलते हैं।
  • cid: से संदर्भित संलग्न हिस्सा। ईमेल कई हिस्सों वाला MIME संदेश होता है। HTML में <img src="cid:logo123"> लिखा होता है और Content-ID: <logo123> तथा Content-Transfer-Encoding: base64 वाला एक अलग हिस्सा इमेज के बाइट ले जाता है। ईमेल में इनलाइन इमेज के लिए यही मानक तरीका है।

दोनों भीतर से Base64 हैं, पर इन्हें निकालने का तरीका अलग है।

स्थिति 1: HTML में डेटा URI

पेज सोर्स या ईमेल का HTML व्यू खोलें और src="data:image/..." एट्रिब्यूट ढूँढें। इमेज देखने का सबसे तेज़ तरीका है data:image/png;base64, प्रीफ़िक्स समेत पूरा मान कॉपी करना और उसे हमारे Base64 से इमेज कन्वर्टर में पेस्ट करना। वह पूर्वावलोकन दिखाता है और बिना कुछ अपलोड किए PNG, JPG या WebP के रूप में डाउनलोड करने देता है।

किसी बड़ी फ़ाइल से सारी इमेज अपने-आप निकालने के लिए एक छोटी Python स्क्रिप्ट इस्तेमाल करें:

import base64, re

html = open("page.html", encoding="utf-8").read()
pattern = r'data:image/(png|jpeg|gif|webp);base64,([A-Za-z0-9+/=\s]+)'

for i, (ext, b64) in enumerate(re.findall(pattern, html)):
    data = base64.b64decode("".join(b64.split()))
    with open(f"image{i}.{ext}", "wb") as f:
        f.write(data)

"".join(b64.split()) उन नई पंक्तियों को हटाता है जो ईमेल सिस्टम लंबी पंक्तियों को लपेटते समय जोड़ते हैं। Python के अन्य विवरणों के लिए Python में Base64 देखें।

स्थिति 2: .eml फ़ाइल में अटैचमेंट

संदेश को .eml के रूप में सहेजें (अधिकांश क्लाइंट में "डाउनलोड" या "इस रूप में सहेजें" होता है)। Python का मानक email पैकेज MIME समझता है और आपके लिए Base64 डिकोडिंग कर देता है:

from email import policy
from email.parser import BytesParser

with open("message.eml", "rb") as f:
    msg = BytesParser(policy=policy.default).parse(f)

for n, part in enumerate(msg.walk()):
    if part.get_content_maintype() != "image":
        continue
    data = part.get_payload(decode=True)      # Base64 already decoded
    name = part.get_filename()
    if not name:
        cid = (part["Content-ID"] or f"image{n}").strip("<>")
        name = f"{cid}.{part.get_content_subtype()}"
    with open(name, "wb") as out:
        out.write(data)

get_payload(decode=True) के साथ लाइब्रेरी Content-Transfer-Encoding हेडर संभालती है, इसलिए हिस्सा Base64 हो या quoted-printable, यह काम करता है।

यदि आपके पास केवल किसी MIME हिस्से का कच्चा टेक्स्ट है, तो Content-Transfer-Encoding: base64 के नीचे की खाली पंक्ति के बाद वाला ब्लॉक कॉपी करें और उसे decodeb64.com या इमेज कन्वर्टर में पेस्ट करें। ब्लॉक के भीतर की नई पंक्तियाँ कोई समस्या नहीं हैं।

स्थिति 3: ब्राउज़र से

वेब पेज पर आप टेक्स्ट को पूरी तरह छोड़ सकते हैं:

  • इमेज पर राइट-क्लिक करें, "इमेज को नए टैब में खोलें" चुनें और फिर सहेजें। ब्राउज़र आपके लिए डेटा URI डिकोड कर देते हैं।
  • या DevTools खोलें, Elements पैनल में <img> एलिमेंट चुनें और src एट्रिब्यूट कॉपी करें।
  • कंसोल में fetch(img.src).then(r => r.blob()) डिकोड किए गए बाइट को Blob के रूप में लौटाता है जिसे आप डाउनलोड कर सकते हैं।

पहले अक्षरों से फ़ॉर्मेट पहचानें

यदि डेटा URI प्रीफ़िक्स गायब है, तो Base64 के पहले अक्षर फ़ाइल का प्रकार बता देते हैं:

  • iVBORw0KGgo — PNG
  • /9j/ — JPEG
  • R0lGOD — GIF
  • UklGR — WebP (RIFF कंटेनर)
  • PHN2Zy या PD94bWw — SVG या XML टेक्स्ट
  • JVBERi0 — PDF, इमेज नहीं

हमारी बाइनरी फ़ाइलें डिकोड करने की गाइड में लंबी सूची है। सहेजते समय सही एक्सटेंशन इस्तेमाल करें, वरना फ़ाइल शायद न खुले।

छोटी इमेज आमतौर पर ट्रैकर होती हैं

यदि किसी ईमेल में 1×1 पिक्सेल की इमेज है, तो वह लगभग हमेशा ट्रैकिंग पिक्सेल होती है, जिससे पता चलता है कि संदेश खोला गया। उसे डिकोड करने पर एक खाली या पारदर्शी वर्ग दिखेगा। डेटा URI वाले पिक्सेल कहीं संपर्क नहीं करते, पर URL से लोड होने वाला पिक्सेल करता है, इसीलिए कई क्लाइंट रिमोट इमेज को डिफ़ॉल्ट रूप से ब्लॉक करते हैं।

परिणामों को सुरक्षित रूप से संभालें

  • SVG में स्क्रिप्ट हो सकती है। किसी अनजान ईमेल के SVG को सीधे ब्राउज़र में न खोलें, और उसे innerHTML से पेज में कभी इंजेक्ट न करें।
  • घोषित प्रकार पर भरोसा न करें। image/png लेबल वाला हिस्सा कुछ और हो सकता है। ऊपर दिखाए अनुसार पहले कुछ बाइट जाँचें।
  • फ़िशिंग संदेश सामग्री को Base64 में छिपाते हैं। अपनी मशीन पर डिकोड करके देखना ठीक है; एम्बेडेड लिंक पर क्लिक करना या संलग्न फ़ाइलें चलाना नहीं।
  • गोपनीयता। किसी निजी इमेज को ऑनलाइन उपकरण में पेस्ट करने से वह अपलोड हो जाती है, जब तक कि उपकरण स्थानीय रूप से न चलता हो। decodeb64.com आपके ब्राउज़र में डिकोड करता है, इसलिए डेटा कभी आपके डिवाइस से बाहर नहीं जाता।

यदि डिकोडिंग विफल हो

आम संदिग्ध हैं: स्ट्रिंग में रह गया data:...;base64, प्रीफ़िक्स, मान के भीतर खाली स्थान या HTML एंटिटी (जैसे + की जगह &#43;), और सहेजते समय कटा हुआ संदेश। Base64 डिकोडिंग क्यों विफल होती है हर स्थिति के लिए एक छोटी सूची से गुज़रता है।
