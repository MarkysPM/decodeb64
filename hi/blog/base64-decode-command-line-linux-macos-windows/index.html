कमांड लाइन पर Base64 डिकोड करें: Linux, macOS और Windows

नवंबर 2026 · 6 मिनट का पठन

Base64 डिकोड करने के लिए आपको ब्राउज़र या स्क्रिप्ट की ज़रूरत नहीं है। हर प्रमुख ऑपरेटिंग सिस्टम में ऐसा उपकरण आता है जो यह काम एक पंक्ति में कर देता है, जो तब काम आता है जब आप SSH पर लॉग पढ़ रहे हों, पाइपलाइन में किसी टोकन की जाँच कर रहे हों या CI वेरिएबल से कोई फ़ाइल बहाल कर रहे हों। यह गाइड Linux, macOS और Windows के कमांड और उन छोटे अंतरों को कवर करती है जिनके कारण वे विफल होते हैं।

Linux: base64 कमांड

GNU coreutils में लगभग हर डिस्ट्रीब्यूशन पर base64 शामिल है। डिकोड करने के लिए -d (या --decode) जोड़ें:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

जब मान किसी वेरिएबल से आए तो printf '%s' या echo -n का उपयोग करें, ताकि अंत की नई पंक्ति इनपुट का हिस्सा न बने:

printf '%s' "$TOKEN" | base64 -d

किसी फ़ाइल को दूसरी फ़ाइल में डिकोड करने के लिए आउटपुट को रीडायरेक्ट करें। बाइनरी परिणाम हमेशा फ़ाइल में भेजें, टर्मिनल पर नहीं:

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

GNU base64 इनपुट में नई पंक्तियाँ सहन कर लेता है पर बाकी कचरे को base64: invalid input से अस्वीकार कर देता है। -i (--ignore-garbage) विकल्प उसे वर्णमाला से बाहर के अक्षर छोड़ने देता है, जो उपयोगी है पर खराब डेटा छिपा सकता है, इसलिए इसे सोच-समझकर इस्तेमाल करें।

macOS: वही उपकरण, थोड़े अलग फ़्लैग

macOS में BSD संस्करण आता है। पुराने रिलीज़ डिकोड करने के लिए बड़े अक्षर वाला -D इस्तेमाल करते हैं, और नए -d भी स्वीकार करते हैं। यदि एक फ़्लैग एरर दे, तो दूसरा आज़माएँ:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

BSD उपकरण -i और -o से फ़ाइलें पढ़ता और लिखता है:

base64 -D -i encoded.txt -o photo.png

macOS पर आप क्लिपबोर्ड से सीधे भी डिकोड कर सकते हैं, जो अभी कॉपी की गई चीज़ को जाँचने का सबसे तेज़ तरीका है:

pbpaste | base64 -D

Linux पर इसके समकक्ष के लिए xclip -o या wl-paste का उपयोग होता है।

Windows: PowerShell

PowerShell सीधे .NET को कॉल कर सकता है। FromBase64String bytes लौटाता है, इसलिए जब सामग्री टेक्स्ट हो तो उन्हें टेक्स्ट में बदलें:

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

Base64 से फ़ाइल बहाल करने के लिए:

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

.NET इनपुट के खाली स्थान और नई पंक्तियों को अनदेखा करता है, इसलिए लपेटी गई फ़ाइल या Get-Content -Raw की अंतिम नई पंक्ति से कोई समस्या नहीं होती। लेकिन अमान्य अक्षरों और गलत लंबाई पर वह एरर देता है। [IO.File]::WriteAllBytes के साथ पूरा पाथ इस्तेमाल करें, क्योंकि .NET सापेक्ष पाथ को प्रोसेस की डायरेक्टरी के आधार पर हल करता है, आपके मौजूदा PowerShell स्थान के आधार पर नहीं।

Windows: certutil

अंतर्निहित certutil क्लासिक कमांड प्रॉम्प्ट से काम करता है और उसे PowerShell की ज़रूरत नहीं है:

certutil -decode encoded.txt photo.png

यह फ़ाइल पढ़ता है, मानक इनपुट नहीं। यह कच्चा Base64 और -----BEGIN ...----- मार्कर वाली PEM-शैली की फ़ाइलें, दोनों स्वीकार करता है, और लिखे गए बाइट की संख्या के साथ सफलता का संदेश दिखाता है।

हर जगह: openssl

यदि OpenSSL इंस्टॉल है, तो वह तीनों सिस्टमों पर एक जैसा व्यवहार करता है:

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

-A फ़्लैग उसे बताता है कि इनपुट एक ही पंक्ति में है। इसके बिना OpenSSL हर 64 अक्षर पर नई पंक्तियाँ अपेक्षित करता है और लंबी एक-पंक्ति स्ट्रिंग पर विफल हो सकता है या कुछ नहीं लौटा सकता।

Base64URL डिकोड करना (JWT के हिस्से और टोकन)

ये उपकरण मानक वर्णमाला की अपेक्षा करते हैं, इसलिए - और _ वाला या = पैडिंग के बिना Base64URL इनपुट एरर देता है। पहले उसे बदलें। एक दोबारा इस्तेमाल होने वाला शेल फ़ंक्शन:

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

वर्णमालाएँ अलग क्यों हैं, इसके लिए Base64 बनाम Base64URL और पेलोड में क्या है, इसके लिए JWT क्लेम की जाँच देखें। PowerShell में यही तर्क FromBase64String को कॉल करने से पहले - और _ को बदलना और पैडिंग जोड़ना है।

जाँचें कि आपने क्या डिकोड किया

डिकोड किया गया आउटपुट टेक्स्ट या कोई भी बाइनरी फ़ाइल हो सकता है। उसे खोलने या चलाने से पहले देख लें:

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

हस्ताक्षर मदद करते हैं: %PDF एक PDF है, PK एक ZIP या Office फ़ाइल है, और स्ट्रिंग की शुरुआत में Base64 टेक्स्ट iVBORw0KGgo एक PNG है। कभी भी ऐसी डिकोड की गई फ़ाइल न चलाएँ जिसकी आपने अपेक्षा नहीं की थी। इस पर और बाइनरी फ़ाइलें डिकोड करने में।

समस्या निवारण

  • invalid input (Linux) या error decoding (macOS): मान में संभवतः data:...;base64, प्रीफ़िक्स, URL-सुरक्षित अक्षर या भटके हुए उद्धरण चिह्न हैं। पहले उन्हें हटाएँ।
  • आउटपुट कचरा है: सामग्री बाइनरी है। उसे टर्मिनल की बजाय फ़ाइल में लिखें।
  • कुछ प्रिंट नहीं हुआ या कट गया: जाँचें कि नई पंक्ति गायब तो नहीं, OpenSSL के साथ -A तो नहीं छूटा, या क्या शेल ने +, / या = को विशेष रूप से संभाल लिया क्योंकि मान उद्धरण चिह्नों में नहीं था।
  • Linux पर चलता है, macOS पर विफल: -d और -D के बीच बदलें।

जब कमांड लाइन की डिकोडिंग किसी मान का अर्थ न समझा पाए, तो उसे decodeb64.com में पेस्ट करें। वह वर्णमाला पहचानता है, पैडिंग सुधारता है और बताता है कि परिणाम टेक्स्ट है या फ़ाइल, सब कुछ आपके ब्राउज़र में स्थानीय रूप से।
