Python 中的 Base64：编码与解码字符串、文件和 URL

2026年11月 · 7 分钟阅读

Python 的标准 base64 模块已经提供了处理 Base64 所需的一切。多数人困惑的并不是 API，而是类型系统：Base64 处理的是 *bytes*，而你的大部分数据一开始是 str。弄清这条边界之后，其余都很简单。

编码字符串

b64encode() 接收 bytes 并返回 bytes。要编码文本，必须先把它转成 bytes；要显示结果，通常再把它解码回字符串：

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

直接传入 str 会抛出 TypeError: a bytes-like object is required, not 'str'。这个错误总是意味着你忘了 .encode() 这一步。

解码字符串

b64decode() 接受 bytes 或仅含 ASCII 的 str，返回 bytes。如果内容是文本，请用正确的字符编码解码这些字节：

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

务必明确指定编码。例如 "héllo" 会编码为 aMOpbGxv，因为 é 在 UTF-8 中占两个字节。如果发送方使用了其他编码（如 Latin-1 或 UTF-16），按 UTF-8 解码会抛出 UnicodeDecodeError 或产生乱码。

严格校验

默认情况下 b64decode() 很宽松：它会默默丢弃不在 Base64 字母表中的字符。这对含换行的字符串很方便，但可能掩盖数据损坏。传入 validate=True，遇到任何非法字符都会抛出 binascii.Error：

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

修复 “Incorrect padding”

Python 中最常见的 Base64 错误是 binascii.Error: Incorrect padding。它表示字符串长度不是 4 的倍数，常见于被去掉 = 的 Base64URL 值（如 JWT 的各个部分）。解码前先把它们补回来：

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

表达式 -len(s) % 4 给出缺失的字符数（0、1、2 或 3）。余数为 1 的长度永远不是有效的 Base64，因此长度比 4 的倍数多 1 的字符串是被截断或损坏的，怎么补填充都没用。

URL 安全的 Base64

对于令牌、标识符以及一切要放进 URL 的内容，请使用 URL 安全的变体，它把 + 和 / 换成 - 和 _（参见 Base64 与 Base64URL）：

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

注意 urlsafe_b64encode() 会保留填充。当 JWT 等规范要求无填充形式时，请自行去掉。

编码与解码文件

以二进制模式（"rb" 和 "wb"）打开文件，避免 Python 把内容当作文本解释：

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

由文件构造 Data URI 只需再加一行：

data_uri = f"data:image/png;base64,{b64}"

对于大文件，不要把全部内容加载进内存。该模块提供 base64.encode(input, output) 和 base64.decode(input, output)，在两个二进制文件对象之间流式处理，编码时每 76 个字符插入一个换行。

解码 Data URI 或 JWT 的某一部分

解码前先去掉前缀，因为 data:image/png;base64, 不属于 Base64 数据：

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

调试时查看 JWT 载荷的方法如下（这*不会*验证签名）：

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

关于哪些内容可以放心信任，请阅读我们的 JWT 解码指南。

模块中的其他函数

  • b32encode() 和 b32decode()：Base32，适合 TOTP 密钥这类人类可读的代码。
  • b16encode() 和 b16decode()：纯十六进制。
  • a85encode() 和 b85encode()：更紧凑的编码（约增长 25% 而不是 33%），代价是字母表更大。

出问题时的检查清单

  • 与 bytes 有关的 TypeError：编码前调用 .encode()。
  • Incorrect padding：字符串被截断或 = 被去掉了；补齐到 4 的倍数。
  • validate=True 时出现非法字符：该值很可能是 Base64URL、含有空白，或仍带着 Data URI 前缀。
  • UnicodeDecodeError：解码出的字节不是 UTF-8 文本，可能是图片、压缩数据或其他编码。
