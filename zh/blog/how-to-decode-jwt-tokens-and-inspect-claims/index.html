如何解码 JWT 令牌并查看声明

2026年8月 · 6 分钟阅读

JWT 令牌是现代身份验证系统的基石。无论你是在调试登录问题、检查 API 返回的声明内容,还是想深入了解 OAuth 2.0 的底层运作方式,懂得如何解码 JWT 都是开发者必备的技能。本指南将带你逐步了解整个过程。

JWT 的结构

一个 JWT(JSON Web 令牌)由三部分组成,以点号分隔:

[header].[payload].[signature]

一个真实的 JWT 看起来是这样的:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

每一部分都使用 Base64URL 编码 —— 而不是标准 Base64。Base64URL 会将 + 替换为 -,将 / 替换为 _,并去除 = 填充,使令牌能够安全地用于 HTTP 头和 URL 中。

第一部分 —— 头部(Header)

第一部分编码了一个描述令牌信息的 JSON 对象:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9

解码后:

{"alg":"HS256","typ":"JWT"}

“alg”字段告诉服务器令牌是用哪种加密算法签名的。常见值包括 HS256(HMAC 配合 SHA-256)、RS256(RSA 配合 SHA-256)和 ES256(ECDSA 配合 SHA-256)。

第二部分 —— 负载(声明)

第二部分编码了声明(claims)—— 即令牌携带的数据:

eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ

解码后:

{"sub":"1234567890","name":"John Doe","iat":1516239022}

标准声明名称:

  • sub(subject,主题)—— 通常是用户 ID
  • iat(issued at,签发时间)—— 令牌创建时的 Unix 时间戳
  • exp(expiration,过期时间)—— 令牌过期时的 Unix 时间戳 —— 在调试“令牌已过期”错误时请检查此字段
  • iss(issuer,签发者)—— 创建该令牌的服务器或服务
  • aud(audience,受众)—— 令牌的预期接收方
  • jti(JWT ID)—— 令牌的唯一标识符,用于防止重放攻击

自定义声明可以包含任何数据:用户角色、权限、电子邮件地址、订阅等级 —— 只要应用需要什么都可以。

第三部分 —— 签名(Signature)

第三部分是一个加密签名,而不是 Base64URL 编码的 JSON 对象。它是通过使用密钥对头部和负载进行哈希运算生成的。你无法将它解码为可读文本。只有持有密钥的服务器才能验证它。

逐步解码 JWT

第一步: 从你的应用程序、浏览器开发者工具或 API 响应中复制 JWT 字符串。

第二步: 按点号分割它。你会得到三部分。第三部分(签名)无法解码为人类可读的文本。

第三步: 取第一或第二部分(头部或负载),将其粘贴到 decodeb64.com。该解码器会自动处理 Base64URL —— 无需手动将 - 替换为 + 或将 _ 替换为 /。

第四步: 解码后的 JSON 会显示出声明内容。如果你在调试身份验证问题,请先检查 exp 字段 —— 将 Unix 时间戳转换为可读日期,查看令牌是否已过期。

解码 vs 验证

一个关键的区别:解码 JWT 并不等同于验证它。任何人都可以解码 JWT 负载并读取其中的声明。真正让 JWT 安全的是签名 —— 只有持有正确密钥的服务器才能验证令牌是真实的且未被篡改。

永远不要在应用程序中信任未经服务器端使用正规 JWT 库验证签名的 JWT 声明。解码仅用于检查和调试。

常见的 JWT 调试场景

“令牌无效” — 令牌可能格式错误或已损坏。将其粘贴到解码器中检查结构。

“令牌已过期” — 解码负载并检查 exp 声明。将 Unix 时间戳转换为日期以确认令牌何时过期。

“声明不正确” — 解码负载,查看令牌中实际包含哪些声明。这种问题通常是因为令牌是在权限变更之前签发的。

“签名验证失败” — 这个问题无法通过解码来调试。请检查服务器是否针对头部中指定的算法使用了正确的密钥或公钥。

立即试试

将你的 JWT 粘贴到 decodeb64.com。该工具会自动检测 Base64URL 编码,并解码头部和负载。如果你需要一次检查多个令牌,还可以使用“逐行解码”模式。

对于从事身份验证系统工作的后端和前端开发者来说,解码 JWT 令牌是日常任务之一。理解这种三段式结构,以及解码与验证之间的区别,能让你在遇到身份验证问题时更加从容不迫。
