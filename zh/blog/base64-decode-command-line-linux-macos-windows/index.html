命令行 Base64 解码：Linux、macOS 与 Windows

2026年11月 · 6 分钟阅读

解码 Base64 不需要浏览器或脚本。每个主流操作系统都自带能一行完成这件事的工具，这在你通过 SSH 查看日志、在流水线中检查令牌，或从 CI 变量恢复文件时非常方便。本指南介绍 Linux、macOS 和 Windows 的命令，以及会让它们失败的细微差异。

Linux：base64 命令

GNU coreutils 几乎在每个发行版上都带有 base64。加上 -d（或 --decode）即可解码：

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

当值来自变量时，使用 printf '%s' 或 echo -n，避免末尾换行成为输入的一部分：

printf '%s' "$TOKEN" | base64 -d

要把一个文件解码到另一个文件，重定向输出。二进制结果一定要写入文件，而不是输出到终端：

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

GNU base64 能容忍输入中的换行，但对其他垃圾字符会报 base64: invalid input。-i（--ignore-garbage）选项会让它跳过字母表之外的字符，这很有用，但可能掩盖数据损坏，请有意识地使用。

macOS：同样的工具，选项略有不同

macOS 自带 BSD 版本。较旧的版本用大写 -D 解码，较新的版本也接受 -d。如果一个选项报错，试试另一个：

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

BSD 版本用 -i 和 -o 读写文件：

base64 -D -i encoded.txt -o photo.png

在 macOS 上还可以直接从剪贴板解码，这是检查刚复制内容最快的方法：

pbpaste | base64 -D

在 Linux 上，对应的做法是 xclip -o 或 wl-paste。

Windows：PowerShell

PowerShell 可以直接调用 .NET。FromBase64String 返回字节，所以当内容是文本时请把它转成文本：

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

从 Base64 恢复文件：

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

.NET 会忽略输入中的空白和换行，所以折行的文件或 Get-Content -Raw 末尾的换行都没问题。但遇到非法字符和错误长度时会抛出错误。请使用带完整路径的 [IO.File]::WriteAllBytes，因为 .NET 解析相对路径时依据的是进程目录，而不是你当前在 PowerShell 中的位置。

Windows：certutil

内置的 certutil 可在传统命令提示符中使用，不需要 PowerShell：

certutil -decode encoded.txt photo.png

它读取的是文件，而不是标准输入。它既接受原始 Base64，也接受带 -----BEGIN ...----- 标记的 PEM 风格文件，并会输出一条成功消息及写入的字节数。

通用：openssl

如果安装了 OpenSSL，它在三个系统上行为一致：

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

-A 标志告诉它输入在单行上。没有它的话，OpenSSL 期望每 64 个字符有一个换行，处理很长的单行字符串时可能失败或什么也不返回。

解码 Base64URL（JWT 部分与令牌）

这些工具期望标准字母表，因此含有 - 和 _ 或缺少 = 填充的 Base64URL 输入会产生错误。请先转换。一个可复用的 shell 函数：

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

关于字母表为何不同，参见 Base64 与 Base64URL；关于载荷的内容，参见如何检查 JWT 声明。在 PowerShell 中，同样的逻辑是先替换 - 和 _ 并补上填充，再调用 FromBase64String。

检查你解码出了什么

解码输出可能是文本，也可能是任意二进制文件。打开或运行它之前，先看一看：

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

文件特征会有帮助：%PDF 是 PDF，PK 是 ZIP 或 Office 文件，字符串开头的 Base64 文本 iVBORw0KGgo 是 PNG。绝不要运行你没预料到的解码文件。详见解码二进制文件。

故障排查

  • invalid input（Linux）或 error decoding（macOS）：值里可能带有 data:...;base64, 前缀、URL 安全字符或多余的引号。先把它们去掉。
  • 输出是乱码：内容是二进制。写入文件，不要输出到终端。
  • 没有输出或被截断：检查是否缺少换行、OpenSSL 是否缺少 -A，或值没有加引号导致 shell 对 +、/、= 做了特殊处理。
  • Linux 上可以，macOS 上失败：在 -d 和 -D 之间切换。
