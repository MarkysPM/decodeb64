Base64 in JavaScript: btoa, atob and Unicode Pitfalls

November 2026 · 7 min read

JavaScript gives you two built-in functions for Base64, btoa() and atob(), and they work perfectly for plain ASCII. The trouble starts the moment your text contains an emoji, an accented letter outside Latin-1, or any non-text binary data. This guide shows what the functions really do, why they fail, and the patterns that work in both the browser and Node.js.

The basics: btoa and atob

The names are historical: btoa means "binary to ASCII" (encode) and atob means "ASCII to binary" (decode).

btoa('Hello, World!');
// "SGVsbG8sIFdvcmxkIQ=="

atob('SGVsbG8sIFdvcmxkIQ==');
// "Hello, World!"

Both are available in all modern browsers, in Web Workers, and as globals in current versions of Node.js, Deno and Bun.

The Unicode problem

The key detail is that btoa() does not take "text". It takes a binary string, where every character must have a code point between 0 and 255, and each character is treated as one byte. Anything above 255 throws:

btoa('€');
// Uncaught InvalidCharacterError: String contains an invalid character

btoa('你好');
// Uncaught InvalidCharacterError

Characters such as é (U+00E9) happen to fit inside the 0–255 range, so btoa('café') appears to work, but it silently encodes the Latin-1 byte rather than UTF-8. Another system that decodes the result as UTF-8 will show a broken character. The safe approach is to convert your string to UTF-8 bytes first and encode those.

Encoding Unicode text correctly

Use TextEncoder to get UTF-8 bytes, turn them into a binary string, then call btoa():

function encodeBase64(text) {
  const bytes = new TextEncoder().encode(text);
  let binary = '';
  bytes.forEach(b => { binary += String.fromCharCode(b); });
  return btoa(binary);
}

encodeBase64('€');      // "4oKs"
encodeBase64('你好');   // "5L2g5aW9"

And the reverse with TextDecoder:

function decodeBase64(b64) {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new TextDecoder().decode(bytes);
}

decodeBase64('4oKs');   // "€"

For very large inputs, building a string one character at a time is slow. Process the bytes in chunks (for example 32,768 at a time with String.fromCharCode.apply) to avoid both the slowdown and call-stack limits.

Node.js: use Buffer

In Node.js, Buffer handles UTF-8 and binary data directly, with no workaround needed:

Buffer.from('€', 'utf8').toString('base64');
// "4oKs"

Buffer.from('4oKs', 'base64').toString('utf8');
// "€"

// Base64URL (Node.js 15.7+ and 14.18+)
Buffer.from('hello?>', 'utf8').toString('base64url');

Buffer is also the right tool for files, because you can read a file straight into a buffer and call .toString('base64') on it without ever creating an intermediate string of bytes.

Working with binary data in the browser

To encode a file the user selected, FileReader.readAsDataURL() is usually the simplest option. The result is a data URI, and the Base64 portion is everything after the comma:

const reader = new FileReader();
reader.onload = () => {
  const dataUri = reader.result;           // "data:image/png;base64,iVBORw0..."
  const base64  = dataUri.split(',')[1];   // just the Base64 payload
};
reader.readAsDataURL(file);

To go the other way and turn Base64 back into a downloadable file or an image URL, decode to a Uint8Array, wrap it in a Blob, and create an object URL:

function base64ToBlob(b64, type = 'application/octet-stream') {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new Blob([bytes], { type });
}

const url = URL.createObjectURL(base64ToBlob(b64, 'image/png'));
img.src = url;

This is what an online Base64-to-image converter does behind the scenes. Our Base64 to Image tool runs entirely in your browser using this same approach, so nothing is uploaded.

Base64URL in JavaScript

There is no built-in btoa equivalent for the URL-safe alphabet in browsers, so convert the characters yourself (see Base64 vs Base64URL):

const toBase64Url = b64 =>
  b64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

const fromBase64Url = s => {
  let b64 = s.replace(/-/g, '+').replace(/_/g, '/');
  while (b64.length % 4) b64 += '=';
  return b64;
};

Error handling

atob() throws an InvalidCharacterError if the input contains characters outside the Base64 alphabet. It ignores ASCII whitespace, so line breaks inside a long string are fine, and current implementations accept missing padding as long as the length is not impossible (a length of 4n+1 can never be valid). Always wrap decoding of untrusted input in try/catch:

function safeDecode(b64) {
  try {
    return atob(b64.trim());
  } catch (e) {
    return null;   // not valid Base64
  }
}

Quick reference

  • ASCII text in the browser: btoa / atob.
  • Any Unicode text: TextEncoder or TextDecoder around btoa or atob.
  • Node.js: Buffer.from(...).toString('base64'), which also supports 'base64url'.
  • Files in the browser: FileReader.readAsDataURL() to encode, Blob plus URL.createObjectURL() to decode.
  • Never assume the string is valid: catch errors, and trim whitespace.

If a decode misbehaves and you cannot tell whether the problem is your code or the data, paste the string into decodeb64.com. If it decodes there, the data is fine and the bug is in how your code handles Unicode, padding or the URL-safe alphabet.
