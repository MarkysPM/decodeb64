Base64 in Python: Encode and Decode Strings, Files and URLs

November 2026 · 7 min read

Python ships with everything you need for Base64 in the standard base64 module. The part that confuses most people is not the API but the type system: Base64 works on bytes, while most of your data starts life as str. Once you understand that boundary, the rest is straightforward.

Encoding a string

b64encode() takes bytes and returns bytes. To encode text you must first turn it into bytes, and to display the result you usually decode it back to a string:

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

Passing a str directly raises TypeError: a bytes-like object is required, not 'str'. That error always means you forgot the .encode() step.

Decoding a string

b64decode() accepts either bytes or an ASCII-only str and returns bytes. If the content is text, decode the bytes with the correct character encoding:

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

Always specify the encoding explicitly. For example, "héllo" encodes as aMOpbGxv because the é takes two bytes in UTF-8. If the sender used a different encoding, such as Latin-1 or UTF-16, decoding as UTF-8 will raise UnicodeDecodeError or produce garbled text.

Strict validation

By default b64decode() is lenient: it silently discards characters that are not in the Base64 alphabet. That is convenient for strings with line breaks, but it can hide corrupted data. Pass validate=True to make it raise binascii.Error on any invalid character:

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

Fixing "Incorrect padding"

The most common Python Base64 error is binascii.Error: Incorrect padding. It means the string length is not a multiple of four, which usually happens with Base64URL values (such as JWT parts) where the = signs were removed. Restore them before decoding:

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

The expression -len(s) % 4 gives the number of missing characters (0, 1, 2 or 3). A remainder of 1 character is never valid Base64, so a string whose length is one more than a multiple of four is truncated or corrupt and no amount of padding will fix it.

URL-safe Base64

For tokens, identifiers and anything that goes into a URL, use the URL-safe variants, which replace + and / with - and _ (see Base64 vs Base64URL):

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

Note that urlsafe_b64encode() keeps the padding. Remove it yourself when a specification such as JWT requires the unpadded form.

Encoding and decoding files

Open files in binary mode ("rb" and "wb") so Python does not try to interpret the content as text:

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

Building a data URI from a file takes one more line:

data_uri = f"data:image/png;base64,{b64}"

For large files, avoid loading everything into memory. The module provides base64.encode(input, output) and base64.decode(input, output), which stream between two binary file objects and insert a line break every 76 characters when encoding.

Decoding a data URI or a JWT part

Strip the prefix before decoding, because data:image/png;base64, is not part of the Base64 data:

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

To peek inside a JWT payload for debugging (this does not verify the signature):

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

Other functions in the module

  • b32encode() and b32decode(): Base32, useful for human-readable codes such as TOTP secrets.
  • b16encode() and b16decode(): plain hexadecimal.
  • a85encode() and b85encode(): denser encodings (about 25% overhead instead of 33%), at the cost of a larger alphabet.

Checklist when something fails

  • TypeError about bytes: call .encode() before encoding.
  • Incorrect padding: the string was truncated or the = signs were stripped; pad to a multiple of four.
  • Invalid characters with validate=True: the value is probably Base64URL, contains whitespace, or still has a data URI prefix.
  • UnicodeDecodeError: the decoded bytes are not UTF-8 text. They may be an image, a compressed blob or another encoding.
