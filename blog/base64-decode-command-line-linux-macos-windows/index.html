Base64 Decode on the Command Line: Linux, macOS and Windows

November 2026 · 6 min read

You do not need a browser or a script to decode Base64. Every major operating system ships a tool that does it in one line, which is handy when you are reading logs over SSH, inspecting a token in a pipeline, or restoring a file from a CI variable. This guide covers the commands for Linux, macOS and Windows, and the small differences that make them fail.

Linux: the base64 command

GNU coreutils includes base64 on practically every distribution. Add -d (or --decode) to decode:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

Use printf '%s' or echo -n when the value comes from a variable, so a trailing newline is not part of the input:

printf '%s' "$TOKEN" | base64 -d

To decode a file into another file, redirect the output. Always send binary results to a file and not to the terminal:

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

GNU base64 tolerates line breaks in the input but rejects other junk with base64: invalid input. The -i (--ignore-garbage) option makes it skip characters outside the alphabet, which is useful but can hide corrupted data, so use it deliberately.

macOS: the same tool, slightly different flags

macOS ships the BSD version. Older releases use an uppercase -D to decode, and newer ones also accept -d. If one flag gives an error, try the other:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

The BSD tool reads and writes files with -i and -o:

base64 -D -i encoded.txt -o photo.png

On macOS you can also decode straight from the clipboard, which is the fastest way to inspect something you just copied:

pbpaste | base64 -D

On Linux the equivalent uses xclip -o or wl-paste.

Windows: PowerShell

PowerShell can call .NET directly. FromBase64String returns bytes, so convert them to text when the content is text:

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

To restore a file from Base64:

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

.NET ignores whitespace and line breaks in the input, so a wrapped file or the trailing newline from Get-Content -Raw is fine. It does throw an error on invalid characters and on a wrong length. Use [IO.File]::WriteAllBytes with a full path, because .NET resolves relative paths against the process directory rather than your current PowerShell location.

Windows: certutil

The built-in certutil works from the classic command prompt and does not need PowerShell:

certutil -decode encoded.txt photo.png

It reads a file, not standard input. It accepts raw Base64 as well as PEM-style files with -----BEGIN ...----- markers, and prints a success message with the number of bytes written.

Anywhere: openssl

If OpenSSL is installed it behaves the same on all three systems:

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

The -A flag tells it the input is on a single line. Without it, OpenSSL expects line breaks every 64 characters and may fail or return nothing on a long single-line string.

Decoding Base64URL (JWT parts and tokens)

These tools expect the standard alphabet, so Base64URL input containing - and _ or missing = padding produces errors. Convert it first. A reusable shell function:

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

See Base64 vs Base64URL for why the alphabets differ, and how to inspect JWT claims for what the payload contains. The same logic in PowerShell is a replace on - and _ plus padding before calling FromBase64String.

Check what you decoded

Decoded output can be text or any binary file. Before opening or running it, look at it:

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

Signatures help: %PDF is a PDF, PK is a ZIP or Office file, and the Base64 text iVBORw0KGgo at the start of a string is a PNG. Never execute a decoded file you did not expect. More on this in decoding binary files.

Troubleshooting

  • invalid input (Linux) or error decoding (macOS): the value probably contains a data:...;base64, prefix, URL-safe characters, or stray quotes. Strip those first.
  • Output is garbage: the content is binary. Write it to a file instead of the terminal.
  • Nothing printed or truncated: check for a missing newline, a missing -A with OpenSSL, or a shell that treated +, / or = specially because the value was not quoted.
  • Works on Linux, fails on macOS: switch between -d and -D.
