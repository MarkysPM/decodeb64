How to Decode Base64 Images from HTML Emails and Web Pages

November 2026 · 7 min read

Sometimes the image you need is not a file but a very long string inside an email or a page's source code. Newsletters, invoices, signatures and exported reports often embed pictures as Base64. Getting them back out is simple once you know where they hide and which of the two embedding methods was used.

How images end up inside emails

There are two common ways to put an image into an HTML email:

  • Data URI in the HTML. The image is part of the markup: <img src="data:image/png;base64,iVBORw0KGgo...">. See our guide to data URIs for the syntax. Many email clients, including Gmail, do not display these, so they are rarer in real campaigns.
  • Attached part referenced by cid:. The email is a MIME message with several parts. The HTML says <img src="cid:logo123"> and a separate part with Content-ID: <logo123> and Content-Transfer-Encoding: base64 carries the image bytes. This is the standard approach for inline images in email.

Both are Base64 under the hood, but you extract them differently.

Case 1: a data URI in HTML

Open the page source or the email's HTML view and find the src="data:image/..." attribute. The quickest way to see the picture is to copy the entire value, including the data:image/png;base64, prefix, and paste it into our Base64 to Image converter. It previews the image and lets you download it as PNG, JPG or WebP without uploading anything.

To pull out every image from a large file automatically, use a short Python script:

import base64, re

html = open("page.html", encoding="utf-8").read()
pattern = r'data:image/(png|jpeg|gif|webp);base64,([A-Za-z0-9+/=\s]+)'

for i, (ext, b64) in enumerate(re.findall(pattern, html)):
    data = base64.b64decode("".join(b64.split()))
    with open(f"image{i}.{ext}", "wb") as f:
        f.write(data)

The "".join(b64.split()) removes line breaks that email systems add when they wrap long lines. For other Python details see Base64 in Python.

Case 2: attachments in an .eml file

Save the message as .eml (most clients have "Download" or "Save as"). Python's standard email package understands MIME and does the Base64 decoding for you:

from email import policy
from email.parser import BytesParser

with open("message.eml", "rb") as f:
    msg = BytesParser(policy=policy.default).parse(f)

for n, part in enumerate(msg.walk()):
    if part.get_content_maintype() != "image":
        continue
    data = part.get_payload(decode=True)      # Base64 already decoded
    name = part.get_filename()
    if not name:
        cid = (part["Content-ID"] or f"image{n}").strip("<>")
        name = f"{cid}.{part.get_content_subtype()}"
    with open(name, "wb") as out:
        out.write(data)

With get_payload(decode=True) the library handles the Content-Transfer-Encoding header, so it works whether the part is Base64 or quoted-printable.

If you only have the raw text of one MIME part, copy the block that follows the blank line under Content-Transfer-Encoding: base64 and paste it into decodeb64.com or the image converter. Line breaks inside the block are not a problem.

Case 3: from the browser

On a web page you can skip the text entirely:

  • Right-click the image and choose "Open image in new tab", then save it. Browsers decode data URIs for you.
  • Or open DevTools, select the <img> element in the Elements panel and copy the src attribute.
  • In the Console, fetch(img.src).then(r => r.blob()) returns the decoded bytes as a Blob you can download.

Identify the format from the first characters

If the data URI prefix is missing, the first characters of the Base64 reveal the file type:

  • iVBORw0KGgo — PNG
  • /9j/ — JPEG
  • R0lGOD — GIF
  • UklGR — WebP (RIFF container)
  • PHN2Zy or PD94bWw — SVG or XML text
  • JVBERi0 — a PDF, not an image

Our guide to decoding binary files has a longer list. Use the right extension when you save, otherwise the file may not open.

Tiny images are usually trackers

If an email contains a 1×1 pixel image, it is almost always a tracking pixel used to detect that the message was opened. Decoding it will show a blank or transparent square. Data URI pixels do not phone home, but a pixel loaded from a URL does, which is why many clients block remote images by default.

Handle the results safely

  • SVG can contain scripts. Do not open an SVG from an unknown email directly in the browser, and never inject it into a page with innerHTML.
  • Do not trust the declared type. A part labeled image/png may be something else. Check the first bytes as shown above.
  • Phishing messages hide content in Base64. Decoding and viewing on your own machine is fine; clicking embedded links or running attached files is not.
  • Privacy. Pasting a private image into an online tool uploads it unless the tool works locally. decodeb64.com decodes in your browser, so the data never leaves your device.

If decoding fails

The usual culprits are the data:...;base64, prefix left in the string, whitespace or HTML entities inside the value (such as &#43; instead of +), and a message that was truncated when saved. Why Base64 decoding fails walks through a short checklist for each.
