Base64 en JavaScript: btoa, atob y las trampas de Unicode

Noviembre de 2026 · 7 min de lectura

JavaScript ofrece dos funciones integradas para Base64, btoa() y atob(), y funcionan perfectamente con ASCII. Los problemas empiezan en cuanto el texto contiene un emoji, una letra acentuada fuera de Latin-1 o datos binarios. Esta guía explica qué hacen realmente las funciones, por qué fallan y los patrones que funcionan tanto en el navegador como en Node.js.

Lo básico: btoa y atob

Los nombres son históricos: btoa significa "binary to ASCII" (codificar) y atob "ASCII to binary" (decodificar).

btoa('Hello, World!');
// "SGVsbG8sIFdvcmxkIQ=="

atob('SGVsbG8sIFdvcmxkIQ==');
// "Hello, World!"

Ambas están disponibles en todos los navegadores modernos, en Web Workers y como globales en las versiones actuales de Node.js, Deno y Bun.

El problema de Unicode

El detalle clave es que btoa() no recibe "texto". Recibe una *cadena binaria*, donde cada carácter debe tener un code point entre 0 y 255 y se trata como un byte. Cualquier valor superior lanza un error:

btoa('€');
// Uncaught InvalidCharacterError: String contains an invalid character

btoa('你好');
// Uncaught InvalidCharacterError

Caracteres como é (U+00E9) caben en el rango 0–255, así que btoa('café') parece funcionar, pero codifica el byte Latin-1 y no UTF-8. Otro sistema que decodifique el resultado como UTF-8 mostrará un carácter roto. Lo seguro es convertir primero la cadena a bytes UTF-8 y codificar esos bytes.

Codificar texto Unicode correctamente

Usa TextEncoder para obtener los bytes UTF-8, conviértelos en una cadena binaria y llama a btoa():

function encodeBase64(text) {
  const bytes = new TextEncoder().encode(text);
  let binary = '';
  bytes.forEach(b => { binary += String.fromCharCode(b); });
  return btoa(binary);
}

encodeBase64('€');      // "4oKs"
encodeBase64('你好');   // "5L2g5aW9"

Y a la inversa con TextDecoder:

function decodeBase64(b64) {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new TextDecoder().decode(bytes);
}

decodeBase64('4oKs');   // "€"

Con entradas muy grandes, construir la cadena carácter a carácter es lento. Procesa los bytes por bloques (por ejemplo, 32 768 a la vez con String.fromCharCode.apply) para evitar la lentitud y los límites de la pila de llamadas.

Node.js: usa Buffer

En Node.js, Buffer maneja UTF-8 y datos binarios directamente, sin rodeos:

Buffer.from('€', 'utf8').toString('base64');
// "4oKs"

Buffer.from('4oKs', 'base64').toString('utf8');
// "€"

// Base64URL (Node.js 15.7+ and 14.18+)
Buffer.from('hello?>', 'utf8').toString('base64url');

Buffer es también la herramienta adecuada para archivos, porque puedes leer un archivo en un buffer y llamar a .toString('base64') sin crear una cadena intermedia de bytes.

Datos binarios en el navegador

Para codificar un archivo que el usuario ha elegido, lo más sencillo suele ser FileReader.readAsDataURL(). El resultado es una data URI y la parte Base64 es todo lo que va después de la coma:

const reader = new FileReader();
reader.onload = () => {
  const dataUri = reader.result;           // "data:image/png;base64,iVBORw0..."
  const base64  = dataUri.split(',')[1];   // just the Base64 payload
};
reader.readAsDataURL(file);

Para el camino inverso y convertir Base64 en un archivo descargable o en la URL de una imagen, decodifica a un Uint8Array, envuélvelo en un Blob y crea una URL de objeto:

function base64ToBlob(b64, type = 'application/octet-stream') {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new Blob([bytes], { type });
}

const url = URL.createObjectURL(base64ToBlob(b64, 'image/png'));
img.src = url;

Esto es lo que hace por detrás un conversor online de Base64 a imagen. Nuestra herramienta Base64 a Imagen funciona íntegramente en tu navegador con este mismo enfoque, así que no se sube nada.

Base64URL en JavaScript

Los navegadores no tienen un equivalente integrado de btoa para el alfabeto seguro para URL, así que convierte los caracteres tú mismo (consulta Base64 vs Base64URL):

const toBase64Url = b64 =>
  b64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

const fromBase64Url = s => {
  let b64 = s.replace(/-/g, '+').replace(/_/g, '/');
  while (b64.length % 4) b64 += '=';
  return b64;
};

Gestión de errores

atob() lanza un InvalidCharacterError si la entrada contiene caracteres fuera del alfabeto Base64. Ignora los espacios en blanco ASCII, así que los saltos de línea en una cadena larga no dan problemas, y las implementaciones actuales aceptan el relleno ausente siempre que la longitud no sea imposible (una longitud de 4n+1 nunca es válida). Envuelve siempre la decodificación de entradas no confiables en try/catch:

function safeDecode(b64) {
  try {
    return atob(b64.trim());
  } catch (e) {
    return null;   // not valid Base64
  }
}

Referencia rápida

  • Texto ASCII en el navegador: btoa / atob.
  • Cualquier texto Unicode: TextEncoder o TextDecoder alrededor de btoa o atob.
  • Node.js: Buffer.from(...).toString('base64'), que también admite 'base64url'.
  • Archivos en el navegador: FileReader.readAsDataURL() para codificar, Blob más URL.createObjectURL() para decodificar.
  • No des por válida la cadena: captura errores y recorta los espacios.

Si una decodificación falla y no sabes si el problema está en tu código o en los datos, pega la cadena en decodeb64.com. Si allí se decodifica, los datos están bien y el fallo está en cómo tu código maneja Unicode, el relleno o el alfabeto seguro para URL.
