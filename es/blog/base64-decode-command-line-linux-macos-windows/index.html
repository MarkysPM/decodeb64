Decodificar Base64 en la línea de comandos: Linux, macOS y Windows

Noviembre de 2026 · 6 min de lectura

No necesitas un navegador ni un script para decodificar Base64. Todos los sistemas operativos principales incluyen una herramienta que lo hace en una línea, algo muy útil cuando lees registros por SSH, inspeccionas un token en un pipeline o restauras un archivo desde una variable de CI. Esta guía cubre los comandos para Linux, macOS y Windows, y las pequeñas diferencias que los hacen fallar.

Linux: el comando base64

GNU coreutils incluye base64 en prácticamente todas las distribuciones. Añade -d (o --decode) para decodificar:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

Usa printf '%s' o echo -n cuando el valor venga de una variable, para que un salto de línea final no forme parte de la entrada:

printf '%s' "$TOKEN" | base64 -d

Para decodificar un archivo a otro archivo, redirige la salida. Envía siempre los resultados binarios a un archivo y no a la terminal:

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

base64 de GNU tolera saltos de línea en la entrada pero rechaza otra basura con base64: invalid input. La opción -i (--ignore-garbage) hace que omita los caracteres fuera del alfabeto, lo cual es útil pero puede ocultar datos corruptos, así que úsala con intención.

macOS: la misma herramienta con pequeñas diferencias en las opciones

macOS incluye la versión BSD. Las versiones antiguas usan una -D mayúscula para decodificar, y las nuevas también aceptan -d. Si una opción da error, prueba la otra:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

La herramienta BSD lee y escribe archivos con -i y -o:

base64 -D -i encoded.txt -o photo.png

En macOS también puedes decodificar directamente desde el portapapeles, la forma más rápida de inspeccionar algo recién copiado:

pbpaste | base64 -D

En Linux el equivalente usa xclip -o o wl-paste.

Windows: PowerShell

PowerShell puede llamar a .NET directamente. FromBase64String devuelve bytes, así que conviértelos a texto cuando el contenido sea texto:

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

Para restaurar un archivo desde Base64:

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

.NET ignora los espacios y saltos de línea de la entrada, así que un archivo con líneas ajustadas o el salto final de Get-Content -Raw no dan problema. Sí lanza un error con caracteres inválidos y con una longitud incorrecta. Usa [IO.File]::WriteAllBytes con una ruta completa, porque .NET resuelve las rutas relativas respecto al directorio del proceso y no a tu ubicación actual en PowerShell.

Windows: certutil

El certutil integrado funciona desde el símbolo del sistema clásico y no necesita PowerShell:

certutil -decode encoded.txt photo.png

Lee un archivo, no la entrada estándar. Acepta Base64 sin procesar y también archivos estilo PEM con marcadores -----BEGIN ...-----, e imprime un mensaje de éxito con el número de bytes escritos.

En cualquier sitio: openssl

Si OpenSSL está instalado, se comporta igual en los tres sistemas:

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

La opción -A le indica que la entrada está en una sola línea. Sin ella, OpenSSL espera saltos de línea cada 64 caracteres y puede fallar o no devolver nada con una cadena larga en una línea.

Decodificar Base64URL (partes de JWT y tokens)

Estas herramientas esperan el alfabeto estándar, así que una entrada Base64URL con - y _ o sin el relleno = produce errores. Conviértela primero. Una función de shell reutilizable:

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

Consulta Base64 vs Base64URL para saber por qué difieren los alfabetos y cómo inspeccionar los claims de un JWT para ver qué contiene el payload. La misma lógica en PowerShell es un reemplazo de - y _ más el relleno antes de llamar a FromBase64String.

Comprueba lo que has decodificado

La salida decodificada puede ser texto o cualquier archivo binario. Antes de abrirla o ejecutarla, míralo:

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

Las firmas ayudan: %PDF es un PDF, PK es un ZIP o archivo de Office y el texto Base64 iVBORw0KGgo al comienzo de una cadena es un PNG. No ejecutes nunca un archivo decodificado que no esperabas. Más sobre esto en decodificar archivos binarios.

Solución de problemas

  • invalid input (Linux) o error decoding (macOS): el valor probablemente contiene un prefijo data:...;base64,, caracteres URL-safe o comillas sueltas. Elimínalos primero.
  • La salida es basura: el contenido es binario. Escríbelo en un archivo en vez de en la terminal.
  • No se imprime nada o sale truncado: revisa si falta un salto de línea, si falta -A con OpenSSL o si el shell trató +, / o = de forma especial porque el valor no iba entre comillas.
  • Funciona en Linux y falla en macOS: cambia entre -d y -D.
