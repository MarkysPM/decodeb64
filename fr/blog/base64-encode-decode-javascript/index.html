Base64 en JavaScript : btoa, atob et les pièges d'Unicode

Novembre 2026 · 7 min de lecture

JavaScript propose deux fonctions natives pour le Base64, btoa() et atob(), qui fonctionnent parfaitement avec l'ASCII. Les ennuis commencent dès que le texte contient un emoji, une lettre accentuée hors Latin-1 ou des données binaires. Ce guide montre ce que font réellement ces fonctions, pourquoi elles échouent et les schémas qui marchent dans le navigateur comme dans Node.js.

Les bases : btoa et atob

Les noms sont historiques : btoa signifie « binary to ASCII » (encoder) et atob « ASCII to binary » (décoder).

btoa('Hello, World!');
// "SGVsbG8sIFdvcmxkIQ=="

atob('SGVsbG8sIFdvcmxkIQ==');
// "Hello, World!"

Les deux sont disponibles dans tous les navigateurs modernes, dans les Web Workers et comme globales dans les versions actuelles de Node.js, Deno et Bun.

Le problème d'Unicode

Le point clé : btoa() ne prend pas du « texte ». Elle prend une *chaîne binaire*, où chaque caractère doit avoir un code point entre 0 et 255 et est traité comme un octet. Tout ce qui dépasse 255 déclenche une erreur :

btoa('€');
// Uncaught InvalidCharacterError: String contains an invalid character

btoa('你好');
// Uncaught InvalidCharacterError

Des caractères comme é (U+00E9) tiennent dans la plage 0–255, donc btoa('café') semble fonctionner, mais elle encode l'octet Latin-1 et non l'UTF-8. Un autre système qui décode le résultat en UTF-8 affichera un caractère cassé. La méthode sûre consiste à convertir d'abord la chaîne en octets UTF-8 puis à encoder ces octets.

Encoder correctement du texte Unicode

Utilisez TextEncoder pour obtenir les octets UTF-8, transformez-les en chaîne binaire, puis appelez btoa() :

function encodeBase64(text) {
  const bytes = new TextEncoder().encode(text);
  let binary = '';
  bytes.forEach(b => { binary += String.fromCharCode(b); });
  return btoa(binary);
}

encodeBase64('€');      // "4oKs"
encodeBase64('你好');   // "5L2g5aW9"

Et l'inverse avec TextDecoder :

function decodeBase64(b64) {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new TextDecoder().decode(bytes);
}

decodeBase64('4oKs');   // "€"

Pour de très grandes entrées, construire la chaîne caractère par caractère est lent. Traitez les octets par blocs (par exemple 32 768 à la fois avec String.fromCharCode.apply) pour éviter la lenteur et les limites de la pile d'appels.

Node.js : utilisez Buffer

Dans Node.js, Buffer gère directement l'UTF-8 et les données binaires, sans contournement :

Buffer.from('€', 'utf8').toString('base64');
// "4oKs"

Buffer.from('4oKs', 'base64').toString('utf8');
// "€"

// Base64URL (Node.js 15.7+ and 14.18+)
Buffer.from('hello?>', 'utf8').toString('base64url');

Buffer est aussi l'outil adapté aux fichiers, car vous pouvez lire un fichier dans un buffer et appeler .toString('base64') sans créer de chaîne d'octets intermédiaire.

Données binaires dans le navigateur

Pour encoder un fichier choisi par l'utilisateur, FileReader.readAsDataURL() est généralement le plus simple. Le résultat est une data URI, et la partie Base64 est tout ce qui suit la virgule :

const reader = new FileReader();
reader.onload = () => {
  const dataUri = reader.result;           // "data:image/png;base64,iVBORw0..."
  const base64  = dataUri.split(',')[1];   // just the Base64 payload
};
reader.readAsDataURL(file);

Pour faire le chemin inverse et transformer du Base64 en fichier téléchargeable ou en URL d'image, décodez vers un Uint8Array, enveloppez-le dans un Blob et créez une URL d'objet :

function base64ToBlob(b64, type = 'application/octet-stream') {
  const binary = atob(b64);
  const bytes = Uint8Array.from(binary, c => c.charCodeAt(0));
  return new Blob([bytes], { type });
}

const url = URL.createObjectURL(base64ToBlob(b64, 'image/png'));
img.src = url;

C'est ce que fait en coulisses un convertisseur en ligne Base64 vers image. Notre outil Base64 vers Image fonctionne entièrement dans votre navigateur avec cette même approche ; rien n'est envoyé.

Base64URL en JavaScript

Il n'existe pas dans les navigateurs d'équivalent natif de btoa pour l'alphabet sûr pour les URL ; convertissez donc les caractères vous-même (voir Base64 vs Base64URL) :

const toBase64Url = b64 =>
  b64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

const fromBase64Url = s => {
  let b64 = s.replace(/-/g, '+').replace(/_/g, '/');
  while (b64.length % 4) b64 += '=';
  return b64;
};

Gestion des erreurs

atob() lève une InvalidCharacterError si l'entrée contient des caractères hors de l'alphabet Base64. Elle ignore les espaces blancs ASCII, donc les retours à la ligne dans une longue chaîne ne posent pas de problème, et les implémentations actuelles acceptent un bourrage manquant tant que la longueur n'est pas impossible (une longueur de 4n+1 n'est jamais valide). Entourez toujours d'un try/catch le décodage d'entrées non fiables :

function safeDecode(b64) {
  try {
    return atob(b64.trim());
  } catch (e) {
    return null;   // not valid Base64
  }
}

Aide-mémoire

  • Texte ASCII dans le navigateur : btoa / atob.
  • Tout texte Unicode : TextEncoder ou TextDecoder autour de btoa ou atob.
  • Node.js : Buffer.from(...).toString('base64'), qui accepte aussi 'base64url'.
  • Fichiers dans le navigateur : FileReader.readAsDataURL() pour encoder, Blob plus URL.createObjectURL() pour décoder.
  • Ne supposez jamais la chaîne valide : interceptez les erreurs et supprimez les espaces.

Si un décodage se comporte mal et que vous ne savez pas si le problème vient de votre code ou des données, collez la chaîne dans decodeb64.com. Si elle s'y décode, les données sont correctes et le bug se trouve dans la façon dont votre code gère Unicode, le bourrage ou l'alphabet sûr pour les URL.
