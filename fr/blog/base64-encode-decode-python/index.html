Base64 en Python : encoder et décoder chaînes, fichiers et URL

Novembre 2026 · 7 min de lecture

Python fournit tout ce qu'il faut pour le Base64 dans le module standard base64. Ce qui déroute la plupart des gens n'est pas l'API mais le système de types : le Base64 travaille sur des *bytes*, alors que presque toutes vos données commencent en str. Une fois cette frontière comprise, le reste est simple.

Encoder une chaîne

b64encode() prend des bytes et renvoie des bytes. Pour encoder du texte, il faut d'abord le convertir en bytes, et pour afficher le résultat on le redécode généralement en chaîne :

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

Passer directement une str déclenche TypeError: a bytes-like object is required, not 'str'. Cette erreur signifie toujours que vous avez oublié l'étape .encode().

Décoder une chaîne

b64decode() accepte des bytes ou une str uniquement ASCII et renvoie des bytes. Si le contenu est du texte, décodez les bytes avec le bon encodage de caractères :

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

Indiquez toujours l'encodage explicitement. Par exemple, "héllo" s'encode en aMOpbGxv car le é occupe deux octets en UTF-8. Si l'émetteur a utilisé un autre encodage, comme Latin-1 ou UTF-16, le décodage en UTF-8 lèvera UnicodeDecodeError ou produira un texte illisible.

Validation stricte

Par défaut, b64decode() est permissif : il écarte silencieusement les caractères hors de l'alphabet Base64. C'est pratique avec des retours à la ligne, mais cela peut masquer des données corrompues. Passez validate=True pour qu'il lève binascii.Error à tout caractère invalide :

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

Corriger « Incorrect padding »

L'erreur Base64 la plus courante en Python est binascii.Error: Incorrect padding. Elle signifie que la longueur de la chaîne n'est pas un multiple de quatre, ce qui arrive souvent avec des valeurs Base64URL (comme les parties d'un JWT) dont les = ont été retirés. Rétablissez-les avant de décoder :

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

L'expression -len(s) % 4 donne le nombre de caractères manquants (0, 1, 2 ou 3). Un reste d'un seul caractère n'est jamais du Base64 valide ; une chaîne dont la longueur dépasse d'un multiple de quatre est donc tronquée ou corrompue et aucun bourrage ne la réparera.

Base64 sûr pour les URL

Pour les jetons, identifiants et tout ce qui va dans une URL, utilisez les variantes URL-safe, qui remplacent + et / par - et _ (voir Base64 vs Base64URL) :

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

Notez que urlsafe_b64encode() conserve le bourrage. Supprimez-le vous-même quand une spécification comme JWT exige la forme sans bourrage.

Encoder et décoder des fichiers

Ouvrez les fichiers en mode binaire ("rb" et "wb") pour que Python n'essaie pas d'interpréter le contenu comme du texte :

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

Construire une data URI à partir d'un fichier ne demande qu'une ligne de plus :

data_uri = f"data:image/png;base64,{b64}"

Pour les gros fichiers, évitez de tout charger en mémoire. Le module propose base64.encode(input, output) et base64.decode(input, output), qui font passer les données en flux entre deux fichiers binaires et insèrent un retour à la ligne tous les 76 caractères à l'encodage.

Décoder une data URI ou une partie de JWT

Retirez le préfixe avant de décoder, car data:image/png;base64, ne fait pas partie des données Base64 :

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

Pour jeter un œil à la charge utile d'un JWT lors d'un débogage (cela ne vérifie *pas* la signature) :

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

Pour en savoir plus sur ce qu'on peut croire en toute sécurité, lisez notre guide de décodage JWT.

Autres fonctions du module

  • b32encode() et b32decode() : Base32, utile pour des codes lisibles comme les secrets TOTP.
  • b16encode() et b16decode() : hexadécimal simple.
  • a85encode() et b85encode() : encodages plus denses (environ 25 % de surcharge au lieu de 33 %), au prix d'un alphabet plus grand.

Check-list en cas d'échec

  • TypeError sur les bytes : appelez .encode() avant d'encoder.
  • Incorrect padding : la chaîne a été tronquée ou ses = retirés ; complétez jusqu'à un multiple de quatre.
  • Caractères invalides avec validate=True : la valeur est probablement du Base64URL, contient des espaces ou conserve un préfixe de data URI.
  • UnicodeDecodeError : les bytes décodés ne sont pas du texte UTF-8. Ce peut être une image, un blob compressé ou un autre encodage.
