Decodificar Base64 na linha de comando: Linux, macOS e Windows

Novembro de 2026 · 6 min de leitura

Você não precisa de navegador nem de script para decodificar Base64. Todo sistema operacional importante traz uma ferramenta que faz isso em uma linha, o que é útil quando você lê logs por SSH, inspeciona um token em um pipeline ou restaura um arquivo a partir de uma variável de CI. Este guia cobre os comandos para Linux, macOS e Windows e as pequenas diferenças que os fazem falhar.

Linux: o comando base64

O GNU coreutils inclui o base64 em praticamente todas as distribuições. Adicione -d (ou --decode) para decodificar:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d
# Hello, World!

Use printf '%s' ou echo -n quando o valor vier de uma variável, para que uma quebra de linha final não faça parte da entrada:

printf '%s' "$TOKEN" | base64 -d

Para decodificar um arquivo em outro arquivo, redirecione a saída. Sempre envie resultados binários para um arquivo, nunca para o terminal:

base64 -d encoded.txt > photo.png
file photo.png
# photo.png: PNG image data, 800 x 600, 8-bit/color RGBA

O base64 do GNU tolera quebras de linha na entrada, mas rejeita outras sujeiras com base64: invalid input. A opção -i (--ignore-garbage) faz com que ele pule caracteres fora do alfabeto, o que é útil mas pode esconder dados corrompidos, então use com intenção.

macOS: a mesma ferramenta, com flags um pouco diferentes

O macOS traz a versão BSD. Versões antigas usam um -D maiúsculo para decodificar, e as novas também aceitam -d. Se uma flag der erro, tente a outra:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -D
echo 'SGVsbG8sIFdvcmxkIQ==' | base64 -d     # newer macOS versions

A ferramenta BSD lê e escreve arquivos com -i e -o:

base64 -D -i encoded.txt -o photo.png

No macOS você também pode decodificar direto da área de transferência, a forma mais rápida de inspecionar algo que acabou de copiar:

pbpaste | base64 -D

No Linux o equivalente usa xclip -o ou wl-paste.

Windows: PowerShell

O PowerShell pode chamar o .NET diretamente. FromBase64String devolve bytes, então converta para texto quando o conteúdo for texto:

$bytes = [Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')
[Text.Encoding]::UTF8.GetString($bytes)
# Hello, World!

Para restaurar um arquivo a partir de Base64:

$b64 = Get-Content .\encoded.txt -Raw
[IO.File]::WriteAllBytes("$PWD\photo.png", [Convert]::FromBase64String($b64))

O .NET ignora espaços e quebras de linha na entrada, então um arquivo com linhas quebradas ou a quebra final do Get-Content -Raw não é problema. Ele lança erro para caracteres inválidos e para tamanho errado. Use [IO.File]::WriteAllBytes com um caminho completo, porque o .NET resolve caminhos relativos a partir do diretório do processo e não da sua posição atual no PowerShell.

Windows: certutil

O certutil embutido funciona no prompt de comando clássico e não precisa de PowerShell:

certutil -decode encoded.txt photo.png

Ele lê um arquivo, não a entrada padrão. Aceita Base64 puro e também arquivos no estilo PEM com marcadores -----BEGIN ...-----, e imprime uma mensagem de sucesso com o número de bytes escritos.

Em qualquer lugar: openssl

Se o OpenSSL estiver instalado, ele se comporta igual nos três sistemas:

echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d -A

A flag -A informa que a entrada está em uma única linha. Sem ela, o OpenSSL espera quebras de linha a cada 64 caracteres e pode falhar ou não devolver nada com uma string longa em linha única.

Decodificando Base64URL (partes de JWT e tokens)

Essas ferramentas esperam o alfabeto padrão, então uma entrada Base64URL com - e _ ou sem o preenchimento = gera erros. Converta antes. Uma função de shell reutilizável:

b64url_decode() {
  local s="${1//-/+}"
  s="${s//_//}"
  case $(( ${#s} % 4 )) in
    2) s="$s==" ;;
    3) s="$s=" ;;
  esac
  printf '%s' "$s" | base64 -d
}

# Inspect the payload of a JWT (this does not verify the signature)
b64url_decode "$(echo "$JWT" | cut -d. -f2)" | jq .

Veja Base64 vs Base64URL para entender por que os alfabetos diferem e como inspecionar claims de JWT para saber o que o payload contém. A mesma lógica no PowerShell é um replace de - e _ mais o preenchimento antes de chamar FromBase64String.

Confira o que você decodificou

A saída decodificada pode ser texto ou qualquer arquivo binário. Antes de abrir ou executar, olhe:

base64 -d encoded.txt | file -          # identify the type
base64 -d encoded.txt | xxd | head      # first bytes in hex

As assinaturas ajudam: %PDF é um PDF, PK é um ZIP ou arquivo do Office, e o texto Base64 iVBORw0KGgo no início de uma string é um PNG. Nunca execute um arquivo decodificado que você não esperava. Mais sobre isso em decodificar arquivos binários.

Solução de problemas

  • invalid input (Linux) ou error decoding (macOS): o valor provavelmente tem um prefixo data:...;base64,, caracteres URL-safe ou aspas soltas. Remova-os antes.
  • A saída é lixo: o conteúdo é binário. Grave em um arquivo em vez de no terminal.
  • Nada impresso ou truncado: verifique se falta uma quebra de linha, se falta -A no OpenSSL ou se o shell tratou +, / ou = de forma especial porque o valor estava sem aspas.
  • Funciona no Linux, falha no macOS: alterne entre -d e -D.

Quando uma decodificação na linha de comando não esclarece um valor, cole-o em decodeb64.com. Ele detecta o alfabeto, repara o preenchimento e diz se o resultado é texto ou arquivo, tudo localmente no seu navegador.
