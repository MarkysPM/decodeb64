Как декодировать изображения Base64 из HTML-писем и веб-страниц

Ноябрь 2026 · 7 мин чтения

Иногда нужное изображение — не файл, а очень длинная строка внутри письма или исходного кода страницы. Рассылки, счета, подписи и выгруженные отчёты часто встраивают картинки в виде Base64. Достать их несложно, если знать, где они прячутся и какой из двух способов встраивания использован.

Как изображения попадают в письма

Есть два распространённых способа поместить изображение в HTML-письмо:

  • Data URI в HTML. Изображение — часть разметки: <img src="data:image/png;base64,iVBORw0KGgo...">. Синтаксис описан в нашем руководстве по data URI. Многие почтовые клиенты, включая Gmail, их не отображают, поэтому в реальных рассылках они встречаются реже.
  • Вложенная часть, на которую ссылается cid:. Письмо — это MIME-сообщение из нескольких частей. В HTML написано <img src="cid:logo123">, а отдельная часть с Content-ID: <logo123> и Content-Transfer-Encoding: base64 несёт байты изображения. Это стандартный подход для встроенных изображений в почте.

Оба варианта — Base64 под капотом, но извлекаются по-разному.

Случай 1: data URI в HTML

Откройте исходный код страницы или HTML-представление письма и найдите атрибут src="data:image/...". Быстрее всего увидеть картинку, скопировав всё значение, включая префикс data:image/png;base64,, и вставив его в наш конвертер Base64 в изображение. Он покажет превью и позволит скачать PNG, JPG или WebP, ничего не загружая.

Чтобы автоматически извлечь все изображения из большого файла, используйте короткий скрипт на Python:

import base64, re

html = open("page.html", encoding="utf-8").read()
pattern = r'data:image/(png|jpeg|gif|webp);base64,([A-Za-z0-9+/=\s]+)'

for i, (ext, b64) in enumerate(re.findall(pattern, html)):
    data = base64.b64decode("".join(b64.split()))
    with open(f"image{i}.{ext}", "wb") as f:
        f.write(data)

"".join(b64.split()) убирает переносы строк, которые почтовые системы добавляют при переносе длинных строк. Подробнее о Python — в статье Base64 в Python.

Случай 2: вложения в файле .eml

Сохраните письмо как .eml (в большинстве клиентов есть «Скачать» или «Сохранить как»). Стандартный пакет email в Python понимает MIME и сам выполняет декодирование Base64:

from email import policy
from email.parser import BytesParser

with open("message.eml", "rb") as f:
    msg = BytesParser(policy=policy.default).parse(f)

for n, part in enumerate(msg.walk()):
    if part.get_content_maintype() != "image":
        continue
    data = part.get_payload(decode=True)      # Base64 already decoded
    name = part.get_filename()
    if not name:
        cid = (part["Content-ID"] or f"image{n}").strip("<>")
        name = f"{cid}.{part.get_content_subtype()}"
    with open(name, "wb") as out:
        out.write(data)

С get_payload(decode=True) библиотека учитывает заголовок Content-Transfer-Encoding, так что это работает, будь часть в Base64 или quoted-printable.

Если у вас есть только «сырой» текст одной MIME-части, скопируйте блок, следующий за пустой строкой под Content-Transfer-Encoding: base64, и вставьте его в decodeb64.com или в конвертер изображений. Переносы строк внутри блока не проблема.

Случай 3: через браузер

На веб-странице можно вообще обойтись без текста:

  • Щёлкните изображение правой кнопкой мыши, выберите «Открыть изображение в новой вкладке» и сохраните. Браузеры сами декодируют data URI.
  • Или откройте DevTools, выберите элемент <img> на панели Elements и скопируйте атрибут src.
  • В консоли fetch(img.src).then(r => r.blob()) возвращает декодированные байты в виде Blob, который можно скачать.

Определение формата по первым символам

Если префикс data URI отсутствует, первые символы Base64 выдают тип файла:

  • iVBORw0KGgo — PNG
  • /9j/ — JPEG
  • R0lGOD — GIF
  • UklGR — WebP (контейнер RIFF)
  • PHN2Zy или PD94bWw — SVG или текст XML
  • JVBERi0 — PDF, а не изображение

В нашем руководстве по декодированию двоичных файлов список подлиннее. При сохранении используйте правильное расширение, иначе файл может не открыться.

Крошечные изображения — обычно трекеры

Если письмо содержит изображение размером 1×1 пиксель, это почти всегда пиксель отслеживания, по которому определяют, что письмо открыто. После декодирования вы увидите пустой или прозрачный квадрат. Пиксели в виде data URI никуда не обращаются, а загружаемые по URL — обращаются, поэтому многие клиенты по умолчанию блокируют удалённые изображения.

Безопасная работа с результатами

  • SVG может содержать скрипты. Не открывайте SVG из незнакомого письма прямо в браузере и никогда не вставляйте его в страницу через innerHTML.
  • Не доверяйте заявленному типу. Часть с пометкой image/png может оказаться чем-то другим. Проверьте первые байты, как показано выше.
  • Фишинговые письма прячут содержимое в Base64. Декодировать и просматривать на собственном компьютере можно; переходить по встроенным ссылкам или запускать вложенные файлы — нельзя.
  • Конфиденциальность. Вставка личного изображения в онлайн-инструмент загружает его, если инструмент не работает локально. decodeb64.com декодирует в вашем браузере, поэтому данные никогда не покидают ваше устройство.

Если декодирование не удаётся

Обычные подозреваемые — префикс data:...;base64,, оставшийся в строке, пробелы или HTML-сущности внутри значения (например, &#43; вместо +) и письмо, обрезанное при сохранении. В статье Почему не декодируется Base64 для каждого случая есть короткий чек-лист.
