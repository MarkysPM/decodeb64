Base64 в Python: кодирование и декодирование строк, файлов и URL

Ноябрь 2026 · 7 мин чтения

В Python всё необходимое для Base64 есть в стандартном модуле base64. Большинство путает не API, а систему типов: Base64 работает с *байтами*, тогда как почти все ваши данные начинаются как str. Когда эта граница понятна, остальное просто.

Кодирование строки

b64encode() принимает байты и возвращает байты. Чтобы закодировать текст, его сначала нужно превратить в байты, а чтобы показать результат, его обычно декодируют обратно в строку:

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

Передача str напрямую вызывает TypeError: a bytes-like object is required, not 'str'. Эта ошибка всегда означает, что вы забыли шаг .encode().

Декодирование строки

b64decode() принимает байты или str только из ASCII и возвращает байты. Если содержимое — текст, декодируйте байты в правильной кодировке символов:

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

Всегда указывайте кодировку явно. Например, "héllo" кодируется как aMOpbGxv, потому что é занимает два байта в UTF-8. Если отправитель использовал другую кодировку, например Latin-1 или UTF-16, декодирование как UTF-8 вызовет UnicodeDecodeError или даст нечитаемый текст.

Строгая проверка

По умолчанию b64decode() снисходителен: он молча отбрасывает символы, которых нет в алфавите Base64. Это удобно для строк с переносами, но может скрыть повреждённые данные. Передайте validate=True, чтобы на любой недопустимый символ выбрасывалось binascii.Error:

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

Исправление «Incorrect padding»

Самая частая ошибка Base64 в Python — binascii.Error: Incorrect padding. Она означает, что длина строки не кратна четырём, что обычно случается со значениями Base64URL (например, частями JWT), у которых убрали =. Верните их перед декодированием:

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

Выражение -len(s) % 4 даёт число недостающих символов (0, 1, 2 или 3). Остаток в один символ никогда не бывает корректным Base64, поэтому строка, длина которой на единицу больше кратной четырём, обрезана или повреждена, и никакое дополнение её не исправит.

URL-безопасный Base64

Для токенов, идентификаторов и всего, что попадает в URL, используйте URL-безопасные варианты, заменяющие + и / на - и _ (см. Base64 и Base64URL):

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

Обратите внимание, что urlsafe_b64encode() сохраняет дополнение. Уберите его самостоятельно, если спецификация, например JWT, требует форму без дополнения.

Кодирование и декодирование файлов

Открывайте файлы в двоичном режиме ("rb" и "wb"), чтобы Python не пытался трактовать содержимое как текст:

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

Построить data URI из файла можно одной дополнительной строкой:

data_uri = f"data:image/png;base64,{b64}"

Для больших файлов не загружайте всё в память. Модуль предоставляет base64.encode(input, output) и base64.decode(input, output), которые потоково работают между двумя двоичными файловыми объектами и при кодировании вставляют перенос строки каждые 76 символов.

Декодирование data URI или части JWT

Уберите префикс перед декодированием, потому что data:image/png;base64, не входит в данные Base64:

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

Чтобы при отладке заглянуть в полезную нагрузку JWT (это *не* проверяет подпись):

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

О том, чему можно доверять, читайте в нашем руководстве по декодированию JWT.

Другие функции модуля

  • b32encode() и b32decode(): Base32, удобен для читаемых человеком кодов вроде секретов TOTP.
  • b16encode() и b16decode(): обычный шестнадцатеричный вид.
  • a85encode() и b85encode(): более плотные кодировки (около 25 % прироста вместо 33 %) ценой более крупного алфавита.

Чек-лист на случай сбоя

  • TypeError про bytes: вызовите .encode() перед кодированием.
  • Incorrect padding: строка обрезана или = убрали; дополните до кратного четырём.
  • Недопустимые символы при validate=True: значение, вероятно, Base64URL, содержит пробелы или всё ещё имеет префикс data URI.
  • UnicodeDecodeError: декодированные байты — не текст UTF-8. Это может быть изображение, сжатый блок или другая кодировка.
