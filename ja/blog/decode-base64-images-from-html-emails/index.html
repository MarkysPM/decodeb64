HTML メールや Web ページから Base64 画像をデコードする方法

2026年11月 · 7 分で読了

必要な画像がファイルではなく、メールやページのソースコードの中にある非常に長い文字列のこともあります。ニュースレター、請求書、署名、エクスポートされたレポートは、しばしば画像を Base64 として埋め込んでいます。どこに隠れているか、どちらの埋め込み方式かが分かれば、取り出すのは簡単です。

画像がメールに入る仕組み

HTML メールに画像を入れる一般的な方法は 2 つあります。

  • HTML 内のデータ URI。画像はマークアップの一部です：<img src="data:image/png;base64,iVBORw0KGgo...">。構文はデータ URIのガイドをご覧ください。Gmail を含む多くのメールクライアントはこれを表示しないため、実際のキャンペーンでは比較的まれです。
  • cid: で参照される添付パート。メールは複数のパートからなる MIME メッセージです。HTML に <img src="cid:logo123"> とあり、Content-ID: <logo123> と Content-Transfer-Encoding: base64 を持つ別のパートが画像のバイト列を運びます。これがメールのインライン画像の標準的な方法です。

どちらも中身は Base64 ですが、取り出し方が違います。

ケース 1：HTML 内のデータ URI

ページのソースやメールの HTML 表示を開き、src="data:image/..." 属性を探します。画像を見る最速の方法は、data:image/png;base64, のプレフィックスを含む値全体をコピーして、私たちの Base64 画像変換ツールに貼り付けることです。プレビューが表示され、何もアップロードせずに PNG、JPG、WebP としてダウンロードできます。

大きなファイルからすべての画像を自動で取り出すには、短い Python スクリプトを使います。

import base64, re

html = open("page.html", encoding="utf-8").read()
pattern = r'data:image/(png|jpeg|gif|webp);base64,([A-Za-z0-9+/=\s]+)'

for i, (ext, b64) in enumerate(re.findall(pattern, html)):
    data = base64.b64decode("".join(b64.split()))
    with open(f"image{i}.{ext}", "wb") as f:
        f.write(data)

"".join(b64.split()) は、メールシステムが長い行を折り返すときに加える改行を取り除きます。Python の詳細は Python の Base64をご覧ください。

ケース 2：.eml ファイル内の添付

メッセージを .eml として保存します（多くのクライアントに「ダウンロード」や「名前を付けて保存」があります）。Python 標準の email パッケージは MIME を理解し、Base64 のデコードを代わりに行います。

from email import policy
from email.parser import BytesParser

with open("message.eml", "rb") as f:
    msg = BytesParser(policy=policy.default).parse(f)

for n, part in enumerate(msg.walk()):
    if part.get_content_maintype() != "image":
        continue
    data = part.get_payload(decode=True)      # Base64 already decoded
    name = part.get_filename()
    if not name:
        cid = (part["Content-ID"] or f"image{n}").strip("<>")
        name = f"{cid}.{part.get_content_subtype()}"
    with open(name, "wb") as out:
        out.write(data)

get_payload(decode=True) なら、ライブラリが Content-Transfer-Encoding ヘッダーを処理するので、パートが Base64 でも quoted-printable でも動作します。

MIME パートの生テキストしかない場合は、Content-Transfer-Encoding: base64 の下の空行に続くブロックをコピーし、decodeb64.com か画像変換ツールに貼り付けます。ブロック内の改行は問題ありません。

ケース 3：ブラウザーから

Web ページでは、テキストを経由する必要すらありません。

  • 画像を右クリックして「画像を新しいタブで開く」を選び、保存します。ブラウザーがデータ URI を代わりにデコードします。
  • あるいは DevTools を開き、Elements パネルで <img> 要素を選択して src 属性をコピーします。
  • コンソールでは、fetch(img.src).then(r => r.blob()) がデコード済みのバイト列をダウンロード可能な Blob として返します。

最初の数文字で形式を見分ける

データ URI のプレフィックスがない場合でも、Base64 の最初の文字からファイルの種類が分かります。

  • iVBORw0KGgo — PNG
  • /9j/ — JPEG
  • R0lGOD — GIF
  • UklGR — WebP（RIFF コンテナ）
  • PHN2Zy または PD94bWw — SVG または XML テキスト
  • JVBERi0 — PDF（画像ではない）

バイナリファイルのデコードのガイドにはもっと長い一覧があります。保存時には正しい拡張子を使ってください。そうしないとファイルが開けないことがあります。

極小の画像はたいていトラッカー

メールに 1×1 ピクセルの画像が含まれていれば、ほぼ間違いなくメールが開かれたことを検知するための追跡ピクセルです。デコードしても空白か透明な正方形が現れるだけです。データ URI のピクセルは外部と通信しませんが、URL から読み込まれるピクセルは通信します。多くのクライアントが外部画像をデフォルトでブロックするのはこのためです。

結果を安全に扱う

  • SVG にはスクリプトが含まれることがあります。見知らぬメールの SVG をそのままブラウザーで開いたり、innerHTML でページに挿入したりしないでください。
  • 宣言された種類を信用しない。image/png とラベル付けされたパートが別物のこともあります。上記のように最初のバイトを確認してください。
  • フィッシングメッセージは内容を Base64 に隠します。自分のマシンでデコードして見るのは問題ありませんが、埋め込まれたリンクをクリックしたり添付ファイルを実行したりしてはいけません。
  • プライバシー。プライベートな画像をオンラインツールに貼り付けると、ツールがローカルで動作しない限りアップロードされます。decodeb64.com はブラウザー内でデコードするため、データがデバイスの外に出ることはありません。

デコードが失敗した場合

よくある原因は、文字列に残った data:...;base64, プレフィックス、値の中の空白や HTML エンティティ（+ の代わりに &#43; など）、そして保存時に切り詰められたメッセージです。Base64 のデコードが失敗する理由では、それぞれについて短いチェックリストを示しています。
