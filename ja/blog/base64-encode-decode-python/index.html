Python の Base64：文字列、ファイル、URL のエンコードとデコード

2026年11月 · 7 分で読了

Python では、Base64 に必要なものすべてが標準の base64 モジュールに揃っています。多くの人が戸惑うのは API ではなく型システムです。Base64 は*バイト列*を扱いますが、手元のデータはたいてい str から始まります。この境界を理解すれば、あとは簡単です。

文字列のエンコード

b64encode() は bytes を受け取り、bytes を返します。テキストをエンコードするには、まず bytes に変換する必要があり、結果を表示するには通常、文字列にデコードし直します。

import base64

text = "Hello, World!"
encoded = base64.b64encode(text.encode("utf-8"))
print(encoded)                    # b'SGVsbG8sIFdvcmxkIQ=='
print(encoded.decode("ascii"))    # SGVsbG8sIFdvcmxkIQ==

str をそのまま渡すと TypeError: a bytes-like object is required, not 'str' になります。このエラーは、.encode() を忘れたという意味です。

文字列のデコード

b64decode() は bytes または ASCII のみの str を受け取り、bytes を返します。内容がテキストなら、正しい文字エンコーディングでバイト列をデコードします。

raw = base64.b64decode("SGVsbG8sIFdvcmxkIQ==")
print(raw)                    # b'Hello, World!'
print(raw.decode("utf-8"))    # Hello, World!

エンコーディングは必ず明示してください。たとえば "héllo" は、é が UTF-8 で 2 バイトを占めるため aMOpbGxv にエンコードされます。送信側が Latin-1 や UTF-16 など別のエンコーディングを使っていた場合、UTF-8 としてデコードすると UnicodeDecodeError になるか、文字化けします。

厳密な検証

デフォルトでは b64decode() は寛容で、Base64 のアルファベットにない文字を黙って捨てます。改行を含む文字列には便利ですが、壊れたデータを隠すことがあります。validate=True を渡すと、不正な文字があれば binascii.Error が発生します。

import binascii

try:
    data = base64.b64decode(user_input, validate=True)
except binascii.Error as e:
    print("Not valid Base64:", e)

「Incorrect padding」の修正

Python で最もよくある Base64 エラーは binascii.Error: Incorrect padding です。文字列の長さが 4 の倍数でないことを意味し、= が取り除かれた Base64URL の値（JWT の各部分など）でよく起こります。デコード前に復元してください。

def b64decode_padded(s: str) -> bytes:
    s = s.strip()
    s += "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s)

式 -len(s) % 4 は、不足している文字数（0、1、2、3）を返します。余りが 1 文字になる長さは決して有効な Base64 になりません。したがって、長さが 4 の倍数より 1 大きい文字列は切り詰められたか壊れており、パディングを足しても直りません。

URL セーフな Base64

トークン、識別子、URL に入るものには、+ と / を - と _ に置き換える URL セーフ版を使います（Base64 と Base64URLを参照）。

token = base64.urlsafe_b64encode(b"\xfb\xff")
print(token)                      # b'-_8='

# Strip padding if the receiving system expects it
print(token.rstrip(b"=").decode()) # -_8

urlsafe_b64encode() はパディングを残す点に注意してください。JWT のようにパディングなしの形式を要求する仕様では、自分で取り除きます。

ファイルのエンコードとデコード

Python が内容をテキストとして解釈しないよう、ファイルはバイナリモード（"rb" と "wb"）で開きます。

# File to Base64 string
with open("photo.png", "rb") as f:
    b64 = base64.b64encode(f.read()).decode("ascii")

# Base64 string back to file
with open("copy.png", "wb") as f:
    f.write(base64.b64decode(b64))

ファイルからデータ URI を作るのは、あと 1 行です。

data_uri = f"data:image/png;base64,{b64}"

大きなファイルは、すべてをメモリに読み込まないようにしましょう。このモジュールには base64.encode(input, output) と base64.decode(input, output) があり、2 つのバイナリファイルオブジェクト間をストリーミング処理し、エンコード時には 76 文字ごとに改行を挿入します。

データ URI や JWT の一部のデコード

data:image/png;base64, は Base64 データの一部ではないので、デコード前にプレフィックスを取り除きます。

def decode_data_uri(uri: str) -> bytes:
    header, _, payload = uri.partition(",")
    return base64.b64decode(payload)

デバッグ時に JWT のペイロードをのぞくには次のようにします（これは署名を検証し*ません*）。

import json

def jwt_payload(token: str) -> dict:
    payload = token.split(".")[1]
    payload += "=" * (-len(payload) % 4)
    return json.loads(base64.urlsafe_b64decode(payload))

何を安全に信頼できるかについては、JWT デコードガイドをご覧ください。

モジュール内のその他の関数

  • b32encode() と b32decode()：Base32。TOTP のシークレットのような人が読みやすいコードに便利です。
  • b16encode() と b16decode()：単純な 16 進数。
  • a85encode() と b85encode()：より高密度なエンコーディング（増加は 33% ではなく約 25%）。その代わりアルファベットが大きくなります。

うまくいかないときのチェックリスト

  • bytes に関する TypeError：エンコード前に .encode() を呼ぶ。
  • Incorrect padding：文字列が切り詰められたか = が取り除かれた。4 の倍数になるまでパディングする。
  • validate=True での不正な文字：値がおそらく Base64URL、空白を含む、あるいはデータ URI のプレフィックスが残っている。
  • UnicodeDecodeError：デコードされたバイトは UTF-8 テキストではない。画像、圧縮データ、別のエンコーディングの可能性がある。
